# 《AI 自动化应用平台 PRD v14.1》

> **定位**：一个让用户买到**实测可靠**的 AI 自动化工具、让创作者用积木组装这些工具的平台。
>
> **用户侧第一卖点**：实测通过率印在详情页——买之前就知道它能不能跑。
>
> **创作者侧第一卖点**：拼认证积木、录一遍演示，产出上架级应用。
>
> **核心信条**：**可靠性是测出来的，不是生成出来的。** LLM 负责让创作变简单，认证门槛负责让工具变可靠；只有被验证过的东西才配卖。
>
> **配套文档**：`02-技术架构.md` v8.1；评审依据 `04-评审报告-2026-10-13.md`。

### 0.1 本版相对 v13.0 的核心变化

| 变化 | 动因 |
|---|---|
| 创作范式从"Agent 现场生成代码"改为"认证积木组装 + 演示录制参数化"，LLM 降级为装配工 | 单次测试通过是随机抽样，产出物可靠性从未被测量 |
| 新增"认证流水线"为一等公民：**真实运行**实测 N 次、通过率带样本量印详情页 | 上架门槛在统计上必须能筛选可靠性 |
| Module/Component 二名合一为 **Block（积木）**，成为版本化、独立签名、独立分发的实体 | 修一个积木 → 所有引用工具恢复；认证成本 O(积木数) 而非 O(应用数) |

## 1. 产品定义

**对用户**：一个 AI 自动化工具商店。每个应用详情页印着**实测通过率（带样本量与测量时间）**、维护期截止日、预估 Token 成本。下载、安装、按引导授权，然后运行。运行中需要用户决策的地方（登录、勾选、确认），工具会挂起并提示。

**对应用创作者**（非技术）：一个积木组装工作台。搜积木 → 拖拽连线 → 录一遍演示 → 填参数 → 提交认证 → 看认证报告 → 上架。

**对积木作者**（技术）：为平台贡献经过认证的积木（站点积木 / 通用积木），按被引用量获得收益（阶段 4 开放）。

**对平台**：自营认证积木库起步（阶段 1-2 主要供给），开放生态后通过认证流水线、积木级健康系统、保障金池维持"实测可靠"的承诺。

### 1.1 用户承诺

| 承诺 | 具体含义 |
|---|---|
| **装得上** | 下载 → 验签 → 自动装白名单依赖 → Chromium 首启下载（HTTPS + 哈希校验） |
| **买得明白** | 实测通过率（N 次真实运行实测，含时间窗与测量环境标注）+ 维护期截止日 + Token 成本区间，全部印在详情页 |
| **跑得通** | 模型配置引导 + 凭证本机加密 + 运行时交互面板；跑不通按政策退款（规则见 §13.1） |
| **持续跑得通** | 积木级健康检测 + 应用健康聚合 + 失效通知；修复发生在积木层，一次修复所有引用应用恢复 |
| **坏了有兜底** | 12 个月维护期内失效可按比例退款；保障金池专项赔付 |

### 1.2 详情页信任字段 v2

| 字段 | 说明 |
|---|---|
| **实测通过率（分列）** | "90%（近 20 次真实运行实测，2026-10）"格式；认证通过率（初始）与用户运行成功率（滚动，最小样本 30，不足显示"数据不足"）分列；**所有比率必须带样本量，无样本量不得展示**；C1 认证通过率必须标注"创作者环境实测，平台抽查复核" |
| 认证等级 | C2 公开页认证 / C1 登录流程认证 / C0 未认证（不可上架） |
| 维护期截止日 | 买断含 12 个月维护，期后标注 as-is |
| 预估单次运行 Token 成本区间 | 认证过程顺带测得 |
| 需要登录的站点 | 提前知情 |
| 运行时是否需要人工交互 | 类型清单（登录/勾选/确认等） |
| 高变更频率站点标注 | 含高变更/受防护站点的应用，首屏显著标注 best-effort |
| 含 AI 生成内容标识 | 对外发布类内容必须标注（合规） |
| 失效退款政策 | 维护期内按比例退款（触发条件见 §13.1） |
| **页脚固定声明** | "运行条件与成功率以信任字段为准；平台审核与认证不构成对运行结果的担保" |

## 3. 核心对象模型

```
Capability（系统能力）
  ↓
Block（积木）★一等公民：认证 + 版本 + 独立签名 + 实测通过率
  ↓ 应用创作者组装 / 演示录制参数化
Workflow（积木连线 + 启动表单）
  ↓
Application（引用积木版本，不内嵌积木代码）
  ↕ 横切
Interaction（运行中挂起 → 用户操作 → 恢复）
```

### 3.1 Capability

Runtime 提供的基础能力：Browser、File、Office、AI、Code、Data、API、Credential、Confirm、Interact、Probe（站点结构检测，内部能力）。（WASM、Docker 移至阶段 5。）

### 3.2 Block（积木）

**积木是平台可靠性的基本单元。** 三类：

| 类型 | 示例 | 供给方 |
|---|---|---|
| 站点积木 | 某站点-搜索笔记、某站点-商品详情读取 | 平台自营（阶段 1-2）、积木作者（阶段 4） |
| 通用积木 | Excel 读写、AI 总结、文件整理、定时触发 | 平台自营 |
| 交互积木 | 让用户勾选、请求登录、危险操作确认 | 平台自营（内置） |

积木结构（详见架构文档 §2）：

```
block/
├── block.yaml          # 声明：能力/权限/交互/副作用/依赖/认证信息
├── interface.json      # 输入输出 Schema（JSON Schema 2020-12）
├── interactions.yaml   # 交互声明
├── main.py / index.js / prompt.md
├── requirements.txt    # 仅白名单依赖
└── tests/
    ├── test.yaml
    ├── sample_input.json
    └── golden/         # 黄金运行录制（仅存创作者本机与认证服务端，不随积木包分发）
```

**认证等级**：

| 等级 | 名称 | 认证执行位置 | 适用 | 上架条件 |
|---|---|---|---|---|
| **C2** | 公开页认证 | 平台沙箱（真实运行） | 无登录积木 | 真实运行实测 N≥20；通过率达到 §9.3 同站点等级阈值；环境矩阵 ≥2 OS × ≥2 时段 |
| **C1** | 登录流程认证 | 创作者本机认证器 + 签名上报 + 服务端抽查 | 含登录积木 | 本机真实运行实测 N≥20（环境口径：本机环境 × ≥2 时段）；通过率达到 §9.3 同站点等级阈值；抽查通过 |
| **C0** | 未认证 | — | 草稿、私用 | **不可上架** |

**站点变更分级**（积木与应用共用标注维度）：

| 等级 | 示例 | 认证与展示策略 |
|---|---|---|
| 标准站点 | HN、GitHub、企业内部系统 | C2，通过率 ≥90% 可上架 |
| 中等变更 | 知乎、微博 | C2/C1，通过率 ≥85% 可上架 |
| 高变更频率 | 小红书、1688 | C1/C2，**不设认证下限，强制首屏标注 best-effort** |
| 受防护 | 启用强访问防护的站点 | best-effort + 人工介入概率高，详情页显著说明 |

### 3.3 复合积木（Composite Block，创作者模块）

应用创作者在画布上选中一段连线（1-N 个积木），可打包命名为**"我的模块"**：

- 复合积木是创作者的模块库单元：可复用、可拖拽到其他画布、可作为画布上的单节点（可展开）；
- 接口 = 入口积木的输入 Schema 与出口积木的输出 Schema 自动聚合（创作者可手工裁剪；权限取组成积木权限并集，接口可裁剪、权限不可裁剪）；
- **认证不重复**：复合积木的认证 = 组成积木认证结果的聚合 + 1 次整链验证（含 C1 内层时在本机执行，其余在沙箱；不重跑 N≥20）；
- **可靠性展示**：复合积木与应用**不展示合成通过率**（串联流程的合成值是推算而非实测，任何加权平均都会系统性高估）；详情页展示组成积木各自实测通过率明细 + 整链验证结果（N=1，标注"非统计值"）；
- 副作用与交互声明 = 组成积木的声明并集（画布规则同样生效）；
- **结构约束**：引用图必须无环；嵌套上限 2 层；含 C0（未认证）内层积木的复合积木不可认证、不可用于上架应用；
- 复合积木默认私有（"我的模块库"）；**用于上架应用时自动随应用分发**：发布时自动注册为"随应用分发的受保护实体"（平台签名、买家可解析、作者不可删除被引用的版本、不计入积木市场）；主动分享/上架到积木市场为阶段 4 能力，其定价、维护义务、保证金与分成条款列入阶段 4 前单独设计清单（见 §13.2）。

### 3.4 Workflow 与 Application

- **Workflow**：积木/复合积木拖拽连线，固定 DAG 骨架 + 节点内参数；接口兼容性静态校验；副作用积木（`side_effects: true`）禁止自动重试。
- **Application**：交易单位 = Workflow + 启动表单 Schema + **积木版本锁定文件（lock）** + 信任字段。应用**引用**积木而非内嵌积木；客户端按需拉取签名积木包，本地保留最后可用版本（离线可跑）。
- **lock 语义**：记录精确基准版本 + 允许自动应用的 patch 浮动窗口（同一次版本内）+ 实际生效版本（运行时记录，随更新/回滚改写并留审计）。lock 同样覆盖复合积木引用。


## 4. Interaction Protocol

**所有运行中的"暂停 → 用户操作 → 恢复"是同一件事。** v14 明确三点：

### 4.1 交互类型与控件族

8 种交互类型，**两族控件实现**（工程上一族一套控件，不为每类型单独开发）：

| 族 | 类型 | 控件 |
|---|---|---|
| 表单族 | input / select / confirm / review | 表单控件（按 schema 渲染） |
| 浏览器族 | login / captcha / pick / takeover | 内嵌浏览器 + 提示 + 完成按钮 |

### 4.2 超时分级与挂起（替代 v13 的"超时即失败"）

| 交互类型族 | 默认超时 | 到期行为 |
|---|---|---|
| 表单族 | 10 分钟，可续期 | → `suspended`（任务挂起，通知用户，72h 恢复窗口） |
| 浏览器族 | 2 小时，可续期 | → `suspended`（进入挂起时即提示：浏览器会话将在挂起 2 小时后关闭） |

- 恢复窗口超时 → `cancelled`；
- **副作用安全语义**：挂起/取消不回滚已发生的外部副作用——副作用节点状态按"已完成 / 未开始"二态保守处理，半执行态（请求已发出未收到响应）视为已完成，恢复时向用户提示"该步骤可能已执行，请核查"；副作用积木强制实现幂等键（静态检查强制），确认对话框固定提示"重复执行可能产生重复效果"。

### 4.3 预声明输入 vs 动态交互（不变）

启动表单收集 `user_input_schema`；运行中动态交互走 `runtime.interact.ask()`。同一套协议与控件，宿主不同（创作者调试区 / 用户运行中心）。

### 4.4 有人值守为主 + 尽力自动（D5）

- 支持定时与队列运行（无人发起时的自动执行）；
- 登录、验证码、确认类交互**永不预授权**，触发即挂起等人；
- 凭证仅存本机，登录态有效期内（会话未过期）的流程可无人值守跑完；
- 产品与营销口径按"有人值守自动化"表述，无人值守是尽力而为。


## 5. 基础模块：模型中心与凭证

### 5.1 模型中心

创作者与买家均需自配模型 Key；内置提供商 / 聚合平台 / 自定义提供商三种接入；能力分级 fast/reasoning/vision，未配置回退 fast 并提示。**用户侧 Token 完全用户自付：平台不经手、不代付用户的模型调用。** 平台自营的认证与健康检测属于平台自身质量活动，使用平台自有模型账户，成本列入平台运营成本（见 §9.1）——此项不改变用户侧红线。

首次引导页固定提示："选择境外模型服务时，您的输入与输出将传输至相应境外服务商。"

**认证会话与用户凭证分离**（详见架构 §4.3）：用户凭证仅存本机不变；认证过程中创作者显式授权的临时会话仅用于认证、跑完即焚、可撤销。

### 5.2 凭证管理（不变）

加密仅存本机（DPAPI / Keychain / safeStorage）；服务端不存储；应用无权直接读取；用户可撤销；凭证句柄出现在网络请求体中 = 一票否决不上架。


## 6. 智能层（v14 大幅瘦身）

### 6.1 装配助手 Agent（原"Automation Architect"降级重定义）

LLM 不再现场编写核心自动化代码。职责收敛为三件事：

| 职责 | 说明 |
|---|---|
| **搜与拼** | 理解需求 → 推荐认证积木组合 → 生成连线与参数草案 |
| **参数化** | 把演示录制轨迹中的字面量提升为输入项、识别循环与提取字段、生成启动表单 Schema |
| **草稿生成** | 积木库无覆盖时的逃生舱：生成 C0 草稿积木（私用可用），上架必须转正认证 |

**草稿生成的约束**：调试循环上限 **8 轮**（v13 为 25 轮）；每会话 Token/金额硬上限熔断；每轮留存最优版本，预算耗尽回滚到最优而非最后版本；连续 2 次同指纹失败即终止并转人工。生成的代码与 CodeAct 执行器受同一出口代理与权限中介约束。

### 6.2 质量技能（静态检查，简化）

禁止裸调用 / 禁止非白名单依赖 / 必须生成测试 / 能力声明与实际调用一致 / 交互声明一致 / **副作用声明检查（发布类调用必须对应 confirm 交互，否则审核不通过）** / **副作用积木幂等键强制** / 凭证外传一票否决。

### 6.3 数据飞轮（六库砍为二库）

| 库 | 内容 | 消费者 |
|---|---|---|
| **页面结构特征库** | DOM 结构、selector 稳定性、页面变更频率（不含任何访问控制类字段） | 健康检测、修复、认证环境矩阵 |
| **失败模式库** | 失败归因（failure_class）、修复记录、用户修复确认 | 自修复、认证阈值调优 |

其余库不建设：无明确消费者，且涉及隐私与证据边界。

### 6.4 自修复（声明式 only）

自修复仅限**声明式变更**（selector 配置、参数调整）：触发 → 候选生成 → 沙箱 golden 回放回归（含登录积木在本机回归）→ 创作者确认 → 签名发布新积木 patch 版本 → 自动传播。**代码级变更不走自动更新通道**（见 §9.6）。因平台积木缺陷导致的失效不罚创作者（见 §13.2）。


## 7. 浏览器运行时（措辞治理后）

### 7.1 核心能力

打开浏览器 → 读取页面结构 → 截图 → 分析 → 修改 → 重新执行。调试链路：装配助手 ⇄ MCP ⇄ BrowserAgentBridge ⇄ Browser-Use ⇄ Patchright Chromium ⇄ CDP。

### 7.2 浏览器环境标准化分层

驱动一致性 / 环境一致性 / 节奏控制 / 网络配置（**用户自配代理，平台不提供代理服务**）/ 会话复用 / 结构化执行（对高变更页面采用脚本化稳定执行，结构来自演示录制或站点积木）。各层由浏览器运行时与积木层承载，平台不提供针对特定站点的定制对抗。

### 7.3 站点结构检测（原"探针"）

开发/认证前的标准化检测：访问目标页面 → 采集 DOM 结构、selector 候选、登录流程形态、访问稳定性信号（响应状态、加载成功率、变更频率）→ 生成结构报告 → 写入页面结构特征库。

**检测礼仪（默认强制，统一命名）**：仅公开页、低频、单会话、尊重 robots 协议、UA 与真实浏览器一致、仅对应用/积木声明的目标域名执行、设频次上限；认证批次为版本发布前一次性活动（限频、跨时段），不构成持续监控。

### 7.4 验证码边界（不变，措辞调整）

平台不处理验证码；验证码一律通过 `runtime.interact.ask({type:"captcha"})` 转交用户手动完成后继续。认证与健康检测中命中验证码，该次计为失败（归因 captcha），不以自动方式响应。

### 7.5 账号风险告知

创作者与本机认证过程使用其自身账号，目标站点可能因自身规则对自动化操作进行限制——首次认证前显著告知，风险由账号主体自担（详见 §16.2）。


## 8. Creator Center（重写）

**定位**：积木组装工作台。拼认证积木、录一遍演示，产出上架级应用。

### 8.1 两类角色

| 角色 | 技术要求 | 产出 |
|---|---|---|
| **应用创作者** | 无需编程 | 组装 + 录制参数化 + 提交认证 → Application |
| **积木作者** | 编程 | 认证积木（站点/通用），阶段 4 开放贡献与分成 |

阶段 1-2 积木供给以**平台自营**为主（平台团队用同一套积木规范与认证流水线生产）。

### 8.2 应用创作者主流程（九步）

```
1. 说需求 / 搜积木
   装配助手推荐认证积木组合（展示各积木实测通过率）
                     ↓
2. 画布组装
   拖拽积木连线，接口兼容性自动校验
                     ↓
3. 缺积木 → 演示录制参数化
   内嵌浏览器真人演示一遍 → 系统记录确定性操作轨迹
   → LLM 参数化（字面量→输入项 / 循环 / 提取字段）
   → 生成积木草稿（C0）
                     ↓
4. 配置启动表单（user_input_schema）
                     ↓
5. 本地干跑
   与本机录制比对，接口 Schema 校验
                     ↓
6. 提交认证
   无登录 → 平台沙箱认证（C2，真实运行 N≥20）
   含登录 → 本机认证器（C1，N≥20 + 签名上报）
                     ↓
7. 查看认证报告
   通过率 / 样本量 / 测量环境 / 失败归因
                     ↓
8. 配置应用信息 + 填写信任字段 + 站点合规声明
                     ↓
9. 提交审核 → 上架
```

### 8.3 演示录制参数化（新行为的核心供给方式）

- 创作者在内嵌浏览器中**亲手完成一遍**目标操作（含登录、翻页、勾选）；
- 系统经 CDP 记录：操作轨迹（点击/输入/滚动/等待）+ 每步 DOM 快照 + 网络请求；
- LLM 参数化：把演示中的字面量（搜索词、商品名）提升为输入项；识别重复模式生成循环；标记提取字段生成输出 Schema；
- 产物是**录制轨迹 + 参数化配置**，不是 LLM 发明的代码——工具可靠是因为它本来就是真人真跑通过的确定性回放；
- 回放失败的步骤标记为"脆弱步骤"，提示创作者重新录制该段或改用站点积木。

### 8.4 草稿路径（对话式生成，降级保留）

积木库无覆盖时，"说一句话"生成 C0 草稿积木：私用可用；上架必须通过认证转正。约束见 §6.1（8 轮上限、熔断、best-so-far）。

### 8.5 汇报格式（认证报告替代"测试通过"）

```
积木认证报告：小红书笔记抓取 v1.0.0
认证等级：C1（登录流程认证，本机认证器，创作者环境实测）
实测：20 次真实运行，通过 18 次，通过率 90%（2026-10-01 至 10-12，跨 ≥2 时段）
环境：Windows 11 / Chrome 130 / 住宅网络 / 创作者会话
失败归因：2 次加载超时（网络类）
需要的权限：domain / credential / ai:fast
需要的交互：login（首次）、input（运行中可能补充主题）
站点变更等级：高变更频率 —— best-effort，详情页将显著标注
[提交审核]  [补测 5 次]  [查看失败详情]
```

### 8.6 画布规则（v2）

- 接口兼容性静态校验（Schema 匹配）；
- **副作用积木**（发布、提交、支付类）在画布上以醒目标识显示，且必须后接确认积木（confirm），否则不可保存；
- 副作用积木失败**禁止自动重试**，必须人工确认后重跑；
- **复合积木**：选中一段连线可打包为"我的模块"（规范见 §3.3），存入我的模块库，可拖拽复用、可作为单节点连线；
- 应用保存时生成积木版本锁定文件（lock，语义见 §3.4）。


## 9. 认证与发布（核心章节）

### 9.1 认证流水线

| 项 | 规范 |
|---|---|
| **统计口径** | **详情页展示的实测通过率 = 纯真实运行口径**（对目标站点的真实访问），不含任何录制回放结果；录制回放（golden）仅用于开发干跑与 patch 回归，其结果单独展示为"回归通过率"，两类数据不得混算 |
| 样本量 | 积木：真实运行 N≥20 / 版本；应用：发布前整链验证 1 次（免费额度，复测收费） |
| 环境矩阵 | C2：≥2 OS × ≥2 时段；C1：本机环境 × ≥2 时段；高变更站点记录环境指纹并随通过率披露 |
| 认证批次礼仪 | 版本发布前一次性批次（≤20 次真实访问、跨 ≥48 小时、单会话、限频），不构成持续监控；"次"以完整运行为单位，一次运行内的页面访问计入同一次 |
| 认证中的交互 | 遇 login → 该积木自动转 C1 路径；遇 confirm → 使用积木声明的认证响应脚本（测试夹具）或标记"部分认证"（不可上架）；副作用积木以响应脚本自动执行两遍验证幂等性；命中验证码该次计失败（归因 captcha） |
| AI 调用 | 认证/检测中的模型调用使用平台自有账户（平台质量活动，成本入积木认证成本，见 §5.1） |
| 应用级验证分级 | 全 C2 积木的应用 → 平台沙箱整链 1 次；含 C1 积木的应用 → **创作者本机整链验证**（复用本机认证器，1 次，签名报告） |
| 结果 | 通过率 + 样本量 + 环境 + 失败归因 → 写入认证记录；通过率即详情页初始可靠性分 |
| 成本 | 积木认证平台承担（平台质量投资，30% 抽成的风险对价）；应用认证每版本 1 次免费额度 |

### 9.2 分级执行（D3/D7 落地）

| 积木类型 | 认证执行位置 | 说明 |
|---|---|---|
| 无登录（标准/中变更站点） | 平台沙箱（C2，真实运行） | 环境代表性可接受 |
| 无登录（高变更/受防护站点） | 平台沙箱一次性认证批次 + 用户运行上报聚合；上架后仅 ≤72h 一次公开页探活，无持续定时检测 | 平台不做高频访问者 |
| 含登录（所有站点） | **创作者本机认证器（C1）**：真实运行 N≥20 + 签名认证报告 + 服务端抽查复核 | 凭证不出本机 |

**C1 抽查机制**：按认证报告抽检（每 10 份至少 1 份）；抽查方式为服务端向创作者下发**重测任务**（指定随机参数与时间窗，本机认证器执行并实时流式上报，服务端校验运行结构指纹与环境一致性）；报告与重测不符 → 该积木版本下架、转入保障金池流程、其引用应用标记"积木维护中"（等待修复，不直接下架应用）。

**平台账号池**（D3 附则）：仅在取得目标站点书面合作授权并经平台安全评审后启用（阶段 4 前默认不启用）。

### 9.3 上架阈值

| 站点变更等级 | 上架条件（C1 与 C2 同阈值） |
|---|---|
| 标准 | 通过率 ≥90%（真实运行 N≥20） |
| 中等变更 | ≥85%（真实运行 N≥20） |
| 高变更频率 / 受防护 | 不设下限；强制首屏 best-effort 标注 + 展示实测通过率 |

### 9.4 发布审核清单（合规项）

- 站点合规声明：创作者声明目标站点自动化访问政策知晓情况、数据类型（公开/含个人信息）、是否有对外发布动作；"高变更 + 个人信息输出 + 对外发布"三要素叠加 → 限制上架或人工重点审核（管理后台工作项，见 §12）；
- AI 生成内容标识检查：对外发布类内容必须可标注；
- confirm 覆盖检查：发布类调用无对应 confirm 交互 → 审核不通过；
- 权限最小化检查。

### 9.5 通过率展示规范

所有通过率类字段必须为"XX%（近 N 次，YYYY-MM）"格式；认证通过率与用户运行成功率分列；用户运行成功率最小样本量 30，不足显示"数据不足"；C1 通过率必须标注测量环境（创作者本机）；**复合积木与应用不展示合成/推算通过率，展示组成积木明细 + 整链验证结果（N=1，标注"非统计值"，见 §3.3）**。

### 9.6 patch 与代码变更边界

自动更新通道**仅限声明式变更**（selector 配置、参数、prompt 文案）；任何代码文件变更一律按 minor/major 版本发布，必须重新认证后由应用创作者重新发布。详见架构文档 §3。


## 10. 健康系统（积木级重构）

### 10.1 检测分级（与 D7 对齐）

| 积木类型 | 检测方式 | 频率 |
|---|---|---|
| 无登录（标准/中变更） | 服务端沙箱全量 | 默认 24h，成本超阈值自动降频 |
| 无登录（高变更/受防护） | 低频公开页探活 | ≤72h 一次，**无持续定时全流程检测** |
| 含登录 | **创作者手动触发检测 + 用户运行上报聚合** | **无服务端定时检测** |
| 含交互 | 使用默认响应或跳过，标记"部分检测" | 跟随所属积木 |
| 免费应用 | 同上各档 ×0.5 频率 | 降频 |

### 10.2 健康评分（v2）

- **积木健康** = 认证通过率（初始）+ 用户运行成功率（滚动），**分列展示，均带样本量**；失败归因中 user-side 类不计入积木分（判定矩阵见架构 §8.2）；复合积木健康展示为内层积木健康明细，不合成单一分值；
- **应用健康** = 工作流上各积木健康分的聚合（积木修复后自动恢复，无需逐应用修复）；
- 修复响应时效不进健康分，仅作曝光微调因子；
- 无最小样本量显示"数据不足"，不显示分数；
- 详情页注明："健康评分覆盖公开页检测；含登录态与交互的流程依赖用户运行上报。"


## 11. 用户端功能（变更点）

- **应用商店**：卡片与详情按信任字段 v2 展示；高变更站点应用首屏显著警示；五星评分延后引入（实测通过率就是最好的评分），文字评价保留；详情页页脚固定声明（§1.2）；
- **下载与运行**：首次运行授权页按站点展示"将使用您在 XX 的登录态执行：浏览抓取 / 表单提交 / 对外发布"操作清单 + 账号风险告知一行；付费应用购买页增加数字商品确认勾选；**退款判据锚点**：购买后需完成一次在线激活校验（见 §13.1）；
- **运行中心**：任务队列 + 定时；新增 `suspended`（挂起）状态——用户可"稍后继续"，72h 恢复窗口；交互面板按两族控件渲染；
- **我的模块库**（创作者）：复合积木（我的模块）、认证状态与报告、被引用数、健康分；
- **设置**：账户、通知、数据清理（含交互记录留存策略说明）、版本更新、关于。

- 运营：分类、公告、推荐、活动；
- 安全：审计日志（审核记录与认证报告随版本归档保存 ≥3 年）、安全事件、权限管理。


## 13. 商业模式（v2）

### 13.1 用户

- 免费应用：同过认证门，检测降频，明示无退款承诺，限制橱窗位；
- 付费应用：一次性买断，**含 12 个月维护期**（详情页公示截止日）；维护期内获得积木 patch 更新与失效修复；期后 as-is，创作者可续保（可选付费服务，定价另定）；
- **退款规则（完整口径）**：① 购买后 24h 内未激活且未运行 → 全退（激活校验时间戳为"已运行"判据，防套利）；② 维护期内积木失效超 7 天 → 按剩余维护月份比例退款；③ 失效判定以健康归因为准，user-side 类不算失效；④ 争议期 7 天，平台仲裁；
- **定价**：创作者自主定价（平台提供同类应用价格分布参考，不提供 AI 定价建议）；涨价不影响已购用户；币种与发票规则见创作者协议。

### 13.2 创作者

- 应用买断收入；平台 30% / 创作者 70% 不变；
- **维护保证金 20% 分 6 期释放（双月释放一期，对齐 12 个月维护期）**：
  - 每期可结算部分在跨过 24h 退款窗与 7 天争议期后可提现；
  - 失效期间未释放份额**转入平台保障金池**，专项用于受影响买家赔付与修复激励；
  - **失效归因分级**：站点变更等非创作者过错 → 释放暂停，修复后恢复，不转入保障金池；创作者超期未响应（**超 14 天**未响应修复通知）→ 转入保障金池；**平台积木缺陷导致 → 不罚创作者，由平台赔付（保障金池资金优先，不足部分平台承担）**；
  - 保障金池初始资金由平台注资（30% 抽成的风险对价组成部分）；阶段 2 平台自制应用期间的赔付由平台全额自担；
  - 台账增加 `disputed` 状态与申诉流程；退款与赔付通过**冲正分录**实现，原始分录不可修改（详见架构文档 §10.3）；
- 积木作者收益（阶段 4）：按被认证应用引用量分成；**复合积木市场化的定价、维护义务、保证金与三级分成条款，与积木市场一并列入阶段 4 前单独设计清单**；
- 健康分影响曝光；废弃标记提前 30 天通知，已购用户保留最后版本本地使用权，维护期内废弃按剩余月份比例退款（由平台承担——废弃属创作者主动行为，不影响已购承诺）；
- **重认证成本**：平台积木 major/minor 升级迫使应用重新发布时，应用认证免费额度重置一次；其余复测按 §9.1 收费。


## 14. 核心指标（四要素：测量位置 / 样本窗口 / 归因 / 目标值）

> 注：标注"校准类"的指标以免目标值作为例外，其余指标必须有目标值。

| 指标 | 测量位置 | 窗口 | 归因 | 目标 |
|---|---|---|---|---|
| **买家首次运行成功率**（北极星） | 客户端上报 | 按发布版本累计 | failure_class + user-side 判定（见下） | ≥80%（标准/中变更站点桶） |
| **30 天退款率**（北极星） | 服务端订单 | 滚动 30 天 | 按退款原因 | <5% |
| 创作成功率（草稿/组装 → 提交认证） | 客户端 | 按月滚动 | 卡点步骤分析 | ≥60% |
| **积木覆盖率**（阶段 1 gate） | 桌面实验 | 实验期 | 未覆盖需求分类 | ≥60% |
| 认证通过率 vs 上架后野外出错率相关性（校准类） | 服务端 | 持续校准 | — | 参考目标：相关系数 ≥0.6 |
| 创作耗时与 Token 成本 p50/p95（校准类） | 客户端+ModelRouter | 月 | — | 报告值，用于定价校准 |
| Health 归因 unknown 占比 | 服务端 | 月 | — | <30% |
| 周留存（以"完成一次运行"为留存动作） | 客户端 | 周 | 分买家/创作者 | >40% |
| 上架认证一次通过率（校准类） | 服务端 | 月 | 按失败原因 | 报告值 |
| 标准/中变更站点运行成功率 | 客户端上报 | 发布 12 个月后（运营收敛目标；上架阈值为准入下限） | failure_class | >90% |
| 安全事件 | 服务端审计 | 持续 | egress_denied / permission_denied / update_permission_escalation 等记安全事件规则 | 0 |

**首跑成功率三个判定点**：① user-side 类失败剔除后统计（判定规则见架构文档 §8.2：failure_class × env_class 二维）；② 首次运行进入 suspended 后 72h 恢复窗口内完成 → 计成功；超窗 cancelled → 计失败（有人值守口径）；③ 积木 patch 自动更新后的运行归属按运行时实际生效积木版本归因。

**积木覆盖率实验规程**：30-50 个真实创作需求样本（来源：种子用户访谈 + 竞品社区需求区），由产品团队按公开判定标准评估"认证积木 + 参数化可完成且无需现场代码生成"；实验报告连同判定记录存档。

**user-side 归因**：failure_class 六类（selector_missing / timeout / auth_expired / captcha / network / unknown）× env_class（device / network / account，客户端上报）二维判定；security 类（egress_denied 等）单列，不进成功率分母。

## 16. 合规基线（新增章节）

### 16.1 上线前置

ICP 备案 + EDI 资质评估（撮合抽成模式定性）；协议三件套（用户协议、隐私政策、创作者协议——含站点声明、负面清单：刷单/水军/批量营销评论、保证金归因与申诉条款）；创作者提现前实名认证；交易与审计记录保存 ≥3 年；注册环节年龄声明（建议 16+）。

### 16.2 风险控制设计（已内化到各章）

- 平台服务端不做对高变更/受防护站点与含登录积木的持续定时检测（§9.2/§10.1）；
- 对外发布类动作强制 confirm + AI 内容标识（§9.4）；
- 检测礼仪默认化（§7.3）；账号风险告知（§7.5）；
- 数据输出物个人信息默认脱敏，输出物不得二次分发（写入创作者协议与应用说明）。

### 16.3 平台红线（任何迭代不得触碰）

1. **用户侧** Token 完全用户自付，平台不经手、不代付用户的模型调用（平台自营认证/健康检测使用平台自有账户，属平台质量活动，见 §5.1）；
2. 用户凭证仅存本机，服务端不存储；
3. 平台不处理验证码，一律转人工；
4. 页面内容标记为不可信数据，高风险动作必须用户确认。

### 16.4 措辞治理原则

对外与文档层面统一使用：环境标准化（非对抗性表述）、站点结构检测、页面结构特征库、结构化执行、高变更频率站点、受防护站点（不以具体防护厂商命名）、检测礼仪；不使用对抗性、隐匿性词汇描述运行时能力，不以具体厂商名指称防护体系（完整对照表见 `04-评审报告-2026-10-13.md` §6）。内部保留术语映射表保证工程沟通无损，并同步清理代码注释与提交信息。


## 17. 一句话总结

> **一个让用户买到实测可靠的自动化工具、让创作者用认证积木组装这些工具的平台。**
>
> **认证流水线是第一底座**——可靠性是测出来的（真实运行实测），不是生成出来的。
> **积木是可靠性的基本单元**——修一个，全体恢复。
> **录制是新的供给方式**——真人真跑通过的东西，才变成工具。
> **Browser/CDP Runtime** 能操作真实软件；**Interaction Protocol** 处理人机协作；**健康系统（积木级）** 保障持续能跑。
> **平台自研：认证流水线、积木规范、权限体系、交互协议、健康系统、Marketplace 与结算——这些是壁垒。**
