## 2. 对象模型规范

### 2.1 Block（积木）目录结构

```text
block/
├── block.yaml
├── interface.json
├── interactions.yaml
├── main.py / index.js / prompt.md
├── requirements.txt          # 仅白名单依赖
└── tests/
    ├── test.yaml
    ├── sample_input.json
    └── golden/               # 黄金运行录制——仅存创作者本机与认证服务端，不随积木包分发
```

`block.yaml`（v2 schema）：

```yaml
schema_version: 2
kind: block
name: xhs_note_fetch
version: 1.2.0                # semver；patch=声明式修复（唯一自动更新通道），minor=接口变更，major=破坏性
title: 小红书笔记抓取
site_change_tier: high        # standard / medium / high / protected
side_effects: false           # true 则禁止 DAG 自动重试 + 幂等键强制（lint 强制）
capabilities: [browser, ai_fast, interact_input, interact_login]
permissions:
  - { type: domain, value: "xiaohongshu.com", required: true }
  - { type: credential, value: "xhs_login", required: true }
  - { type: ai, value: "fast", required: true }
  - { type: interact, value: "input", required: true }
  - { type: interact, value: "login", required: true }
runtime:
  adapter: python             # python / node / agent（阶段5: wasm/docker/api）
  entry: main.py
  timeout_sec: 300
reliability:                  # 认证流水线写入，只读
  level: C1                   # C2 公开页 / C1 登录流程 / C0 未认证
  pass_rate: 0.90             # 纯真实运行口径
  samples: 20
  measured_at: 2026-10-12
  environment: creator-local
ai_description: 根据主题抓取某站点首页相关笔记内容
```

`interactions.yaml`：同 v7（id/type/title/schema/optional，login 类型含 site 字段）。副作用积木须额外声明 `default_response`（认证响应脚本用）与 `idempotency_key` 钩子（强制实现）。

### 2.2 Interface Schema 与断言

JSON Schema 2020-12。非确定性输出（AI 总结、抓取结果）断言方式：`test.yaml` 声明 `assertion: schema | golden_similarity`；golden 相似度算法为嵌入余弦 + 字段级数值容差，阈值由认证流水线按积木类型标定（标定记录入认证报告）。

### 2.3 Workflow 执行语义

固定 DAG 骨架 + 节点参数。**v8 硬约束**：

- 每节点输出持久化 checkpoint；续跑 = 跳过已成功节点并注入缓存输出；
- `side_effects: true` 节点：**禁止自动重试**；失败必须经 `runtime.confirm` 人工确认后重跑（对话框固定提示"重复执行可能产生重复效果"）；`idempotency_key` 钩子**强制实现**（lint 静态检查强制，未实现不上架）；
- 挂起/取消不回滚外部副作用：节点状态按"已完成/未开始"二态保守处理，半执行态视为已完成并提示用户核查；
- retryable 判定为**错误码 × 节点副作用属性**二维矩阵（附录 D）。

### 2.4 Application 包格式与 lock 语义

`.aapkg`（zip）——**不内嵌积木**：

```text
app.aapkg
├── app.json            # 含 trust_fields、user_input_schema、maintenance_until
├── manifest.json
├── signature.json      # 应用级签名
├── workflow.json       # 节点 = 积木引用 + 参数 + 连线
├── block-lock.json     # 见下
├── assets/
└── NOTICE
```

**lock 语义（v8.1 统一）**：

```json
{
  "pins": { "xhs_note_fetch": { "base": "1.2.0", "patch_window": "1.2.*" } },
  "effective": { "xhs_note_fetch": "1.2.3" }
}
```

- `base`：发布时认证通过的精确基准版本；
- `patch_window`：允许自动应用的声明式 patch 范围（同一次版本内）；
- `effective`：运行时实际生效版本，随自动更新/回滚改写，每次变更留审计记录；运行归因、健康聚合均以 `effective` 为准。


### 2.5 复合积木（Composite Block）

```yaml
schema_version: 2
kind: composite_block
name: my_xhs_selection
version: 1.0.0
title: 小红书选品模块
nodes:                          # 引用原子积木/其他复合积木 + 参数 + 连线（DAG 子图）
  - { ref: xhs_note_fetch@1.2.0, params: {...} }
  - { ref: ai_selection@2.0.1, params: {...} }
interface: { input: {...}, output: {...} }   # 聚合或手工裁剪
side_effects: false             # 组成积木声明并集
interactions_decl: [review]     # 组成积木声明并集
```

- 认证：组成积木认证结果聚合 + 整链验证 1 次（含 C1 内层在本机执行，其余在沙箱；不重跑 N≥20）；**可靠性不合成单一通过率**——展示组成积木各自实测通过率明细 + 整链验证结果（N=1，标注"非统计值"；串联合成值属推算，禁止以加权平均展示，见 PRD §3.3/§9.5）；
- **结构约束**：引用图必须无环；嵌套上限 2 层；含 C0 内层积木的复合积木不可认证、不可用于上架应用；
- **分发**：复合积木默认私有；用于上架应用时发布时自动注册为"随应用分发的受保护实体"（平台签名、买家可解析、作者不可删除被引用版本、不计入积木市场；Registry 标记 `distribution: app-bound`）；主动上架市场为阶段 4 能力；
- **lock 裁决**：复合积木自身的 lock 条目 `patch_window: null`（composite 仅整体重发布，无自动更新通道）；其**内层原子积木**的声明式 patch 按应用侧展开的 lock 条目走 §3.2 正常通道自动更新（composite 的 effective 仅随整体重发布变更）；同一应用内"直接引用 + 经复合引用"同一原子积木时，统一使用同一条 lock 条目（防 effective 归因分裂）；
- 权限：`permissions_max` = 内层积木权限并集（接口可裁剪、权限不可裁剪）；composite 重发布时重算，扩大则引用应用重新发布时走重新授权；
- Registry 中 `blocks.change_kind` 对复合积木为 `composite`（仅整体重发布，无自动更新通道）。

## 3. Block Registry 与签名分发

### 3.1 Registry（服务端）

```text
blocks(
  name, version, semver_part,
  change_kind,                      # declarative / code / composite —— patch 自动更新仅允许 declarative
  distribution,                     # public / app-bound（复合积木随应用分发）
  interface_hash, permissions_max,  # 权限上限（更新不可扩大）
  pkg_uri, pkg_sha256, signature,
  certification_level, reliability_json,
  deprecated_by, created_at
)
block_refs( app_id, block_name, base_version, patch_window, effective_version )
```

### 3.2 签名与更新通道

- 积木包独立 ed25519 签名；**认证签名密钥与分发签名密钥分离**；
- **patch 内容边界（硬约束）**：`change_kind=declarative`（selector 配置、参数、prompt 文案）才可进入自动更新通道；**发布侧强制校验**——Registry 签名前核对 patch 的文件 diff 仅限声明式资源，违规拒绝签名（不止客户端侧条件检查）；**任何代码文件变更 = minor/major，必须重新认证（真实运行 N≥20）并由应用创作者重新发布**，不存在代码级热更新通道；
- **patch 自动更新前置条件（全部满足）**：change_kind=declarative ∧ semver 兼容 ∧ **权限集不扩大（违反即拒绝——防热更新提权）** ∧ 验签通过 ∧ 本地 smoke test（单次干跑 + 接口 Schema 校验）通过 ∧ 失败自动回滚；
- **灰度**：patch 按引用应用分批推送（5% → 50% → 100%），任一批次 smoke 失败率超阈值即冻结并回滚；运行中任务不热替换，下次运行生效；
- **密钥轮换**：客户端内置多公钥信任集，新旧密钥并行有效期 ≥2 个客户端版本；泄露应急 = 吊销对应密钥 + 强制客户端更新 + 受影响积木重签。

### 3.3 修复传播链路

```text
Health/用户上报发现积木异常
  → 声明式自修复生成 patch 候选
  → 回归：C2 积木在沙箱 golden 回放（mock 网络存根——验证逻辑，不验证站点真实状态）
          C1 积木在本机认证器回归（创作者触发）
  → 创作者确认
  → 签名发布 patch 版本 → 灰度自动更新 → 引用应用恢复
```

含登录积木的**站点真实漂移**检测不依赖沙箱（沙箱无凭证、mock 无站点信号），依赖：创作者触发检测 + 用户运行上报聚合（§9）。


## 4. 认证流水线（核心子系统）

### 4.1 架构

```text
                       ┌────────────────────────────┐
提交积木/应用版本 ──→ │ 认证调度器（服务端 Celery） │
                       └──────┬─────────────┬───────┘
                    C2 分支  │              │  C1 分支
                 ┌──────────▼───┐   ┌──────▼─────────────┐
                 │ 平台沙箱集群  │   │ 创作者本机认证器     │
                 │ 容器+浏览器   │   │ （客户端内置模块）   │
                 │ 真实运行 N≥20 │   │ 真实运行 N≥20 + 签名 │
                 │ + golden 回归 │   │ 认证报告 attestation│
                 └──────┬───────┘   └──────┬─────────────┘
                        └───────┬──────────┘
                          ┌─────▼──────┐
                          │ certification_runs
                          │ 通过率/样本/环境/归因
                          └─────┬──────┘
                     详情页初始可靠性分 ←┘   → 阈值判定 → 上架许可
```

### 4.2 认证执行规范

| 项 | 规范 |
|---|---|
| **统计口径** | **通过率 = 纯真实运行口径**（对目标站点真实访问）；golden 回放结果单列为"回归通过率"，两者不得混算、不得合并展示 |
| 样本 | 积木：真实运行 N≥20/版本；应用：整链验证 1 次（免费额度） |
| 环境矩阵 | C2：≥2 OS × ≥2 时段；**C1：本机环境 × ≥2 时段（单机现实约束的显式降级口径）**；环境指纹（OS/浏览器版本/网络类型/时段）随通过率披露 |
| 批次礼仪 | 版本发布前一次性批次：≤20 次真实访问、跨 ≥48h、单会话、限频；不构成持续监控 |
| 认证中交互 | login → 自动转 C1 路径；confirm → 使用积木声明的 `default_response`（认证响应脚本），未声明 → 标记"部分认证"（不可上架）；副作用积木以响应脚本自动执行两遍验证幂等性；验证码 → 该次计失败（归因 captcha） |
| AI 调用 | 认证/检测中的模型调用使用**平台自有账户**（平台质量活动；成本入积木认证成本） |
| 应用级分级 | 全 C2 积木应用 → 平台沙箱整链 1 次；含 C1 积木应用 → **创作者本机整链验证**（本机认证器复用，1 次，签名报告；规范与积木级 C1 相同） |
| C1 抽查 | 按报告抽检（每 10 份至少 1 份）：服务端下发**重测任务**（随机参数 + 指定时间窗），本机认证器执行并实时流式上报；服务端校验运行结构指纹（步骤序列/时序分布/网络行为形状）与环境一致性；不符 → 积木版本下架 + 保障金池流程 + 引用应用标记"积木维护中" |

`certification_runs(id, subject_type, subject_id, version, level, n, pass, fail_json, env_fingerprint, live_pass_rate, regression_pass_rate, attestation_sig, started_at, finished_at)` —— 同时是数据飞轮的可靠性主数据集。

### 4.3 创作者本机认证器（C1）与信任模型

**信任定位（诚实声明）**：本机认证报告是**创作者自证材料**，用于上架资格初审；其真实可靠性由三道后续机制持续修正：① 抽查重测（4.2）；② 用户运行上报滚动修正详情页展示分；③ 伪造实锤的处置（下架 + 保障金池 + 账号信用降级）。

- 客户端内置模块，复用 Runtime sidecar；
- **设备注册**：首次使用时客户端生成密钥对，公钥经账号绑定注册到服务端（设备指纹入册）；
- **挑战响应**：每次认证开始前向服务端取 nonce，报告签名覆盖 nonce（防重放、防报告转储）；
- 流程：取 nonce → 执行 N≥20 真实运行（参数由认证规范生成）→ 生成认证报告（结构化结果 + 失败归因，**不含页面内容**）→ 签名上报；
- 凭证全程不离开本机；认证会话与用户日常凭证隔离存储，跑完即焚，可撤销；
- 首次使用前显著告知账号风险（PRD §7.5）。


## 5. 录制与回放子系统

### 5.1 演示录制（创作侧）

```text
创作者在内嵌浏览器亲手操作
  ↓ CDP 采集
操作轨迹（click/input/scroll/wait/nav）+ 每步 DOM 快照 + 网络请求
  ↓ 参数化器（LLM）
字面量→输入项；重复模式→循环；提取字段→输出 Schema
  ↓
积木草稿（C0）= 轨迹 + 参数化配置 + interface.json
```

- 回放器按轨迹确定性重放；脆弱步骤（回放失败）标记并提示重录或改用站点积木；
- 录制数据仅存本机；提交认证时上传 golden 子集（**值脱敏为占位符**）。

### 5.2 黄金运行回放（定位与边界）

- 用途一：创作侧本地干跑（§PRD 8.2 步骤 5，使用本机录制，无需随包分发 golden）；
- 用途二：patch 回归（§3.3，沙箱用 mock 网络存根）；
- **用途边界**：golden 回放**不产生**详情页实测通过率，不检测站点真实漂移；站点漂移由三层真实运行覆盖：版本发布时的认证批次（真实运行 N≥20）+ 创作者触发检测（C1/高变更站点）+ 用户运行上报（上架后）。


## 6. Runtime 架构

### 6.1 进程模型

```text
Electron 客户端
  ├── Renderer（UI）
  ├── Main
  ├── 本机认证器（C1）
  ├── Runtime Sidecar（FastAPI）
  │     └── Egress Proxy ←— 组件进程出网唯一通道（强制机制见 6.2）
  ├── Block Update Service
  └── SQLite

服务端（Marketplace / 认证 / Health / 结算）
  ├── API / Worker / Beat
  ├── 认证沙箱集群（容器 + 浏览器）
  ├── PostgreSQL / Redis / MinIO
  └── Block Registry + 签名服务
```

### 6.2 出口代理（F5 修复的完整方案）

**强制机制**（按平台）：

| 平台 | 机制 |
|---|---|
| Windows | **WFP（Windows Filtering Platform）callout/provider**：按进程（sidecar 子进程树）强制将出网流量重定向至本地代理；绕过代理的直连在 WFP 层丢弃 |
| macOS | **PF 规则 + 专属用户/组**：组件进程以专用用户运行，PF 按用户/组规则锚定 redirect 至代理，其余出网丢弃 |
| Linux（阶段 5） | network namespace + iptables/nftables，仅放行代理端口 |

**防御边界（诚实声明）**：出口代理 + 网络强制防"组件进程直连外网"的越权与低成本外泄；**不防蓄意对抗**（与 §6.6 沙箱边界声明一致）——蓄意对抗的主防线仍是依赖白名单 + lint + 审核 + 签名 + 最小权限。实现前置任务：**M05 Spike——Windows WFP 与 macOS PF 双平台技术验证**（阶段 1 第一个迭代内完成）。降级方案两级：一级为容器级隔离本地组件（仅适用于已具备容器环境的场景，消费级 Windows 不依赖）；二级为系统防火墙出站白名单规则（Windows 防火墙 / macOS pf，粒度粗于进程级但零新依赖，作为最低保底）。

**浏览器出网边界**（单独策略，不与组件混同）：

| 流量类型 | 策略 |
|---|---|
| 页面导航主文档 | 仅允许积木声明的 `domain:<host>` |
| 页面子资源（CDN/字体/统计） | 放行并记录（保证页面可用性） |
| 组件经 CDP 在页面内注入的非导航请求（fetch/XHR） | lint 静态禁止 + 运行时 CDP 事件审计：异常域名重复出现 → 告警 + 安全事件 |

### 6.3 执行会话状态机

```text
queued → running → succeeded
              │ → failed（retryable 矩阵判定）
              │ → waiting_user（携带 interaction）
              │      ├─ 用户响应 → running
              │      └─ 超时 → suspended（表单族 10min / 浏览器族 2h，均可续期）
              │ → suspended（用户"稍后继续"；72h 恢复窗口，超时 → cancelled）
              → cancelled
              → partial_succeeded
```

- **组件进程**在 waiting/suspended 期间保持存活（SQLite 持久化会话上下文）；
- **浏览器会话**：进入 suspended 时即提示"浏览器会话将在挂起 2 小时后关闭"；到时关闭。若挂起节点为浏览器族节点，恢复运行时该节点按 checkpoint 做节点级重跑（副作用节点需人工确认）；
- 客户端崩溃/休眠后**不支持组件内恢复**：回退 DAG 节点级重跑（checkpoint 跳过已完成节点）；
- **cancelled 的副作用语义**：不回滚已发生副作用，半执行态保守处理（§2.3）。

### 6.4 Capability API

browser / file / office / ai / code / data / api / credential / confirm / interact / probe。CodeAct 执行器与组件进程同受 PermissionBroker + egress proxy + 资源限制约束，权限取积木声明集。

### 6.5 login → 凭证落库

浏览器族 login 交互完成 → 客户端经 CDP 捕获登录态：**Cookie（主路径）+ token/localStorage 类登录态（覆盖 JWT 型站点，按站点适配器声明采集字段）** → safeStorage 加密落库（credentials 表，关联 credential_id 与站点）→ CredentialBroker 发放不透明 CredentialHandle → 后续运行免登录；有效期与刷新由 CredentialBroker 管理，用户可随时撤销。

### 6.6 沙箱

| 级别 | 机制 | 场景 |
|---|---|---|
| 进程级 | 子进程 + **网络强制（6.2）** + Job Object / setrlimit / sandbox-exec | 本地组件 |
| 容器级 | Docker / containerd | 服务端认证沙箱、不可信组件 |
| WASM 级 | wasmtime | 阶段 5 |

防御边界：进程级防意外不防蓄意；主防线 = 依赖白名单 + lint + 审核 + PermissionBroker + **出口代理**。

### 6.7 组件环境隔离

每组件独立 venv（uv 管理）；依赖仅白名单源 + 锁定哈希；安装期网络过 egress proxy；依赖冲突不跨组件传播。

### 6.8 日志与脱敏

统一 JSONL；内置模式 + 明文集精确替换；上报前二次脱敏；交互记录、认证日志、运行上报走同一脱敏管道。

## 8. Agent 编排（装配助手）

### 8.1 状态机

```text
intake（理解需求）
  → block_search（检索认证积木，展示通过率）
  → assemble（生成连线与参数草案）
      ├─ 覆盖 → param_fill → dry_run → report
      └─ 不覆盖 → record_guide（引导演示录制）→ parameterize
                    └─ 仍不覆盖 → draft_codegen（C0 草稿，逃生舱）
```

### 8.2 归因模型（北极星指标的判定地基）

```text
failure_class 六类：selector_missing / timeout / auth_expired / captcha / network / unknown
env_class 三值（客户端随运行上报）：device / network / account
security 类单列：egress_denied / permission_denied / update_permission_escalation（不进成功率分母，记安全事件）

user-side 判定（不计积木分、从首跑成功率剔除）：
  auth_expired 且 env_class=account（用户凭证问题）
  network 且 env_class=network（用户网络问题）
  其余组合计站点/积木侧
```

错误码（附录 D）与 failure_class 的映射表由 M09 维护；`credential_missing` 等错误码映射到 auth_expired 类。

### 8.3 草稿生成调试循环（硬约束）

```text
codegen → lint → dry_run
    ├─ 通过 → report（C0，标注未认证）
    └─ 失败 → debug_loop（上限 8 轮）
          ├─ Token/金额硬上限熔断（ModelRouter 强制，默认值随站点变更等级分档）
          ├─ 每轮留存 best-so-far，耗尽回滚最优版本
          ├─ 失败指纹 = hash(failure_class + selector/url + error_code)
          └─ 连续 2 次同指纹 → 终止转人工
```

### 8.4 Token 计量

ModelRouter 统一记录 provider/model/tokens/cost；每会话预算熔断（创作者可配）。


## 9. 健康系统（积木级）

### 9.1 检测分级

| 积木类型 | 方式 | 频率 |
|---|---|---|
| 无登录（标准/中变更） | 服务端沙箱全量 | 默认 24h，成本超阈值自动降频 |
| 无登录（高变更/受防护） | 低频公开页探活 | ≤72h 一次，无持续定时全流程检测 |
| 含登录 | **创作者触发检测 + 用户运行上报聚合** | 无服务端定时检测 |
| 含交互 | 默认响应或跳过，标记"部分检测" | 跟随所属积木 |
| 免费应用 | 各档 ×0.5 | 降频 |

`health_checks` 挂 **block_version_id**（积木版本；Block 统一术语，原 component_version_id 已更名）；应用健康 = 工作流上积木健康聚合（按 lock `effective` 版本归因）。

### 9.2 评分与上报

- 积木分 = 认证通过率（初始，纯 live 口径）+ 用户运行成功率（滚动），分列展示带样本量（用户侧最小样本 30，不足显示"数据不足"）；user-side 归因不计积木分（§8.2）；
- 用户运行上报管道：客户端上报 `{app, effective_block_versions, run_result, failure_class, env_class}`，**不含页面内容**；隐私政策披露，设置可关闭；**关闭上报的账号不参与统计，其退款判据改为激活校验时间戳（§10.2）**；
- unknown 归因占比 >30% 触发告警；
- 修复响应时效不进评分，仅作曝光微调。


## 10. Marketplace 与结算

### 10.1 上架状态机

```text
draft → submitted → certifying → in_review → approved → published
published → delisted（平台下架/安全事件） / deprecated（创作者废弃）
certifying 未达阈值 → rejected（附认证报告）→（修订后）→ submitted 可重提
```

> 命名说明：任务挂起态为 `suspended`（§6.3）；上架下架态为 `delisted`，二者不同。

审核清单：认证报告核验 + 站点合规声明 + AI 内容标识 + confirm 覆盖 + 权限最小化。

### 10.2 买断与退款

- 买断含 12 个月维护期（app.json `maintenance_until`）；
- **24h 全退**：购买后 24h 内**未完成在线激活校验** → 全退；**完成激活即视为已开始使用，不再适用 24h 全退**（仍适用维护期失效退款）。激活校验在购买后首次启动客户端时完成，与运行上报开关无关——关闭上报不产生退款套利空间；
- 维护期内失效超 7 天：按剩余维护月份比例退款；失效判定以 Health 归因为准（user-side 不算）；争议期 7 天平台仲裁（管理后台工作台）。

### 10.3 结算、保障金池与冲正

```text
订单支付 ¥P
  ├─ 平台 30%
  └─ 创作者 70%
       ├─ 80% 可结算（提现前实名；跨过 24h 退款窗 + 7 天争议期后可提现）
       └─ 20% 保证金，双月释放一期（共 6 期，对齐 12 个月维护期）
失效归因分级：
  站点变更（非创作者过错）→ 释放暂停，修复后恢复，不转入保障金池
  创作者超 14 天未响应（含抽查重测超期）→ 未释放份额转入保障金池
  平台积木缺陷            → 不罚创作者；平台赔付（保障金池资金优先，不足平台承担）
  废弃                    → 剩余释放暂停；已购保留本地使用权；维护期内废弃退款由平台承担
```

- **保障金池初始资金由平台注资**（30% 抽成的风险对价组成部分）；阶段 2 平台自制应用期间赔付由平台全额自担；
- **台账只增不改 + 冲正分录**：退款/赔付/回补均以冲正分录实现（原分录不可修改），每笔冲正关联原始订单与归因记录；
- **资金追回顺序**：退款发生时 → ① 该订单未释放保证金优先冲抵 → ② 创作者未结算余额冲抵 → ③ 仍不足记平台垫付应收（创作者后续收入优先偿还）；
- 金额一律「分」，时间一律 UTC ISO8601；审计记录与认证报告随版本归档 ≥3 年。


## 11. 权限、凭证与安全模型

### 11.1 权限全链路

积木声明 → 应用聚合（lock）→ 安装授权 → 本地 grants → PermissionBroker + **Egress Proxy（网络强制）** 双闸。权限类型：domain / fs / credential / ai / code_exec / action / probe / interact。

### 11.2 凭证

用户凭证仅存本机、CredentialHandle 不透明、可撤销；认证会话（C1）与用户日常凭证隔离存储、跑完即焚、可撤销。

### 11.3 威胁模型（v8 增量）

| 威胁 | 缓解 |
|---|---|
| 组件外泄登录后页面数据 | **出口代理 + 平台网络强制（6.2）** + API 层 broker + CDP 注入审计 |
| 热更新提权/投毒 | **change_kind=declarative 硬边界** + 权限不扩大 + 认证/分发密钥分离 + 验签 + smoke + 灰度 + 回滚 |
| C1 认证报告伪造 | 自证材料定位 + 设备注册 + nonce 挑战响应 + 抽查重测（4.2/4.3） |
| 副作用重复执行 | side_effects 声明 + 禁自动重试 + confirm 提示 + **幂等键强制（lint）** |
| waiting_user 期间客户端崩溃 | 节点级 checkpoint 重跑 + 副作用人工确认 |
| 退款套利（关闭上报） | 激活校验时间戳判据（10.2） |
| Chromium 首启下载被篡改 | HTTPS + 哈希校验 |
| 签名密钥泄露 | 多公钥信任集 + 轮换并行期 + 吊销应急（3.2） |
| Sidecar 被本机其他进程调用 | named pipe + ACL / 每请求 HMAC |
| 其余（恶意上架、供应链投毒、凭证泄露、页面提示注入、包篡改等） | 同 v7.0 §10.3 继承有效项 |

## 附录 B. 术语（v8.1）

| 术语 | 定义 |
|---|---|
| Block（积木） | 可认证、版本化、独立签名分发的自动化能力单元（原 Module/Component 合一） |
| 认证等级 | C2 公开页认证 / C1 登录流程认证 / C0 未认证 |
| 实测通过率 | **纯真实运行口径**的 N 次实测统计；展示必须带样本量与时间窗；与回归通过率分列 |
| 回归通过率 | golden 回放的通过率，仅用于 patch 回归与开发干跑 |
| 演示录制参数化 | 真人演示 → 操作轨迹 + DOM 快照 → LLM 参数化 → 积木草稿 |
| 黄金运行（golden run） | 录制的确定性运行基准，用于回放回归；不随积木包分发 |
| 认证响应脚本 | 副作用/确认类积木在认证沙箱中使用的默认响应夹具 |
| 站点变更分级 | standard / medium / high / protected（按页面结构变更频率） |
| 站点结构检测 | 开发/认证前的页面结构与稳定性采集（含检测礼仪约束） |
| 出口代理 | 组件出网唯一通道 + 平台网络强制（WFP/PF/netns）；浏览器流量按 6.2 单独策略 |
| side_effects | 积木副作用声明；副作用节点禁 DAG 自动重试、幂等键强制 |
| change_kind | declarative / code / composite——自动更新通道仅限 declarative；composite 仅整体重发布 |
| lock | base 精确基准 + patch_window 浮动窗口 + effective 实际生效版本 |
| 保障金池 | 失效期间未释放保证金的专项用途池（赔付与修复激励），平台初始注资 |
| 维护期 | 买断含 12 个月维护责任窗口 |
| suspended | 任务挂起态（等人，72h 恢复窗口）——与上架下架态 delisted 不同 |
| delisted | 上架下架态（平台下架/安全事件） |
| env_class | 运行环境三值上报：device / network / account（user-side 归因判定维度） |
| 环境标准化分层 | 驱动一致性/环境一致性/节奏控制/网络配置/会话复用/结构化执行 |
| takeover | 人工介入协议 |
| trust_fields | 详情页信任字段（v2：分列通过率、维护期、Token 成本区间、页脚声明） |

## 附录 D. 错误码注册表（v8.1）

| 错误码 | 来源 | retryable | 会话状态转移 | 归因 |
|---|---|---|---|---|
| permission_denied | PermissionBroker | 否 | →failed（记安全事件） | **security** |
| egress_denied | 出口代理 | 否 | →failed（记安全事件） | **security** |
| **update_permission_escalation** | Block Update Service | 否 | 拒绝自动更新，回滚（记安全事件） | **security** |
| credential_missing / revoked | CredentialBroker | 否 | →waiting_user（凭证配置） | auth_expired（env_class=account 时计 user-side） |
| output_schema_violation | 出口校验 | 否 | →failed | unknown |
| component_timeout | watchdog | **副作用节点：否；纯计算：是** | 副作用失败 → waiting_user（confirm） | timeout |
| **side_effect_confirm_required** | DAG executor | 否 | →waiting_user（confirm） | 不映射 |
| resource_exceeded | 资源限制 | 否 | →failed | unknown |
| browser_crash | M06 | 是 | 重启会话后节点级重试 | unknown |
| captcha_detected | 检测器 | 否 | →waiting_user（captcha）；认证中计失败 | captcha |
| intervention_required | M08 | 否 | →waiting_user（takeover） | unknown |
| user_confirm_required | runtime.confirm | 否 | →waiting_user（confirm） | 不映射 |
| dependency_install_failed | 依赖安装器 | 是（重试 1 次） | 安装期错误 | 不映射 |
| signature_invalid | 验签 | 否 | 拒绝安装/更新 | 不映射 |
| runtime_crashed | M01 watchdog | 否 | →failed | unknown |
| selector_missing | 组件约定 | 是（非副作用节点） | 节点级 retry | selector_missing |
| probe_failed | 站点结构检测 | 是（重试 1 次） | 开发期错误 | 不映射 |
| **certification_failed** | 认证流水线 | 否 | 拒绝上架（附报告） | 按 fail_json |
| **attestation_invalid** | C1 抽查 | 否 | 积木下架 + 保障金池流程 | 不映射 |
| interaction_timeout | InteractionBroker | 否 | →**suspended**（72h 窗口） | unknown |
| interaction_invalid_response | InteractionBroker | 否 | →failed | unknown |
| session_expired | 状态机 | 否 | suspended → cancelled | unknown |

failure_class 六类：selector_missing / timeout / auth_expired / captcha / network / unknown；user-side 判定 = failure_class × env_class 二维（§8.2）；security 类单列不进成功率分母。
