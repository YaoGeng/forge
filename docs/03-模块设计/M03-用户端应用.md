# M03 用户端应用 模块设计 v1.0

> **职责**：买家侧全部界面——商店（信任字段 v2 全字段渲染）、购买/激活/授权、My Library、运行中心（队列/定时/挂起恢复/交互面板两族控件）、任务详情与设置。
>
> **上游依据**：`01-产品文档.md` v14.1 §1.2、§4、§11、§13.1；`02-技术架构.md` v8.1 §6.3（状态机宿主）、§9.2、§10.2、§12.3。
>
> **状态**：起草（2026-10-14）。**阶段 2 核心交付（买家闭环）。**


## 1. 职责与边界

| IN（本模块负责） | OUT（不属于本模块） |
|---|---|
| 商店卡片/列表/详情与信任字段 v2 渲染 | 商品、订单与信任字段数据（M10 服务端） |
| 购买页数字商品确认勾选、激活校验触发 | 支付与退款规则判定（M10，架构 §10.2 口径） |
| 首次运行授权页（按站点操作清单） | grants 存储与权限判定（M05 PermissionBroker） |
| My Library（已购应用 + 我的模块入口） | 凭证存储与登录态捕获（M04/M05） |
| 运行中心：任务队列/定时/suspended 恢复 | DAG 执行、checkpoint、状态机（M05） |
| 交互面板两族控件渲染 | Interaction 协议语义与超时规则（M16，本模块消费） |
| 任务详情：步骤/交互历史/错误与修复建议/日志导出 | 失败归因判定与错误码映射（映射表由 **M09 维护**，架构 §8.2；本模块只呈现） |
| 设置：账户/通知/数据清理/上报开关/更新 | 运行上报管道服务端（M11） |

**核心不变量**：
1. 详情页一切通过率均为纯真实运行口径且必须带样本量——无样本量不渲染数字，不足最小样本显示"数据不足"；
2. 页脚固定声明按原文渲染，不可配置、不可移除；
3. 交互面板只按 M16 协议消息渲染（两族控件），不存在积木私有 UI 通道；
4. 运行上报经脱敏管道且设置可关闭；关闭上报不改变激活校验与退款规则锚点（架构 §9.2/§10.2）。

## 3. 关键流程

### 3.1 商店与信任字段 v2 渲染（PRD §1.2 全字段）

| 字段 | 渲染规则 |
|---|---|
| 实测通过率（分列） | "XX%（近 N 次，YYYY-MM）"格式；认证通过率（初始）与用户运行成功率（滚动）分列两个数据项；用户侧最小样本 30，不足显示"数据不足" |
| C1 标注 | C1 认证通过率强制标注"创作者环境实测，平台抽查复核" |
| 认证等级 | C2 公开页认证 / C1 登录流程认证（C0 不可上架，商店不出现） |
| 维护期截止日 | 展示具体日期；期后标注 as-is |
| Token 成本 | 预估单次运行 Token 成本区间 |
| 需要登录的站点 | 站点清单，提前知情 |
| 人工交互 | 类型清单（登录/勾选/确认等，来自 interactions 声明并集） |
| best-effort 警示 | 高变更/受防护站点应用首屏显著标注，不可折叠、不可关闭 |
| AI 内容标识 | 含对外发布动作的应用必须展示 AI 生成内容标识说明（合规） |
| 失效退款政策 | 维护期内按比例退款摘要 + 完整规则入口（PRD §13.1） |
| 页脚固定声明 | 原文："运行条件与成功率以信任字段为准；平台审核与认证不构成对运行结果的担保" |

- 复合积木与应用不渲染合成通过率：展示组成积木各自实测通过率明细 + 整链验证结果（N=1，标注"非统计值"）；
- 卡片与列表：展示精简信任字段（实测通过率带样本量、认证等级、best-effort 标注），完整字段进详情页；
- 文字评价保留展示与提交；无五星评分入口（五星评分延后，PRD §11）。

### 3.2 购买 → 激活 → 下载授权

```text
购买页：信任字段摘要 + 价格 + 数字商品确认勾选（未勾选不可支付）
   文案要点：24h 内未完成激活校验可全退；完成激活即视为已开始使用，
   不再适用 24h 全退（完整文案 TBD（模块细化时定））
  → 支付（M10）
  → 在线激活校验：支付成功即时触发（本次会话完成），启动序列兜底；时间戳落 library 并上报 M10
    （与运行上报开关无关——退款判据锚点，架构 §10.2）
  → 下载 .aapkg → 验签 → 按需拉取签名积木包
    （本地保留最后可用版本，离线可跑）
  → 首次运行授权页：按站点展示"将使用您在 XX 的登录态执行：
    浏览抓取 / 表单提交 / 对外发布"操作清单（应用权限聚合而来）
    + 固定一行账号风险告知（口径 PRD §7.5，文案 TBD（模块细化时定））
  → 授权写入本地 grants（M05 消费；用户可撤销）
```

### 3.3 My Library

- 已购应用：版本、维护期截止日、健康状态（M11）、失效通知入口；
- 失效通知呈现（PRD §1.1"持续跑得通"的用户侧呈现）：修复发生在积木层，引用应用恢复后健康状态自动刷新；
- 我的模块（创作者页签）：复合积木列表——认证状态与报告、被引用数、健康分（复合积木展示内层积木健康明细，不合成单一分值）；画布与编辑归 M02。

### 3.4 运行中心

- 任务列表区分队列任务与定时任务，展示状态、恢复窗口倒计时与运行入口；
- 任务队列 + 定时（有人值守为主 + 尽力自动，PRD §4.4）；**定时/队列调度由 M01 TaskScheduler 承载**（触发时调用 M05 `task.submit`），本模块提供调度管理 UI（新建/编辑/暂停定时任务）；
- 状态视图对齐架构 §6.3：queued / running / waiting_user / suspended / succeeded / failed / cancelled / partial_succeeded；
- **suspended（稍后继续）**：交互超时（表单族 10 分钟 / 浏览器族 2 小时，均可续期）或用户主动挂起 → 通知用户 + 72h 恢复窗口倒计时 → 超窗转 cancelled；浏览器族进入挂起即提示"浏览器会话将在挂起 2 小时后关闭"；
- 恢复运行：checkpoint 节点级续跑；半执行态副作用节点恢复时提示"该步骤可能已执行，请核查"。

### 3.5 交互面板（消费 M16 协议）

| 族 | 类型 | 控件 |
|---|---|---|
| 表单族 | input / select / confirm / review | 表单控件（按 schema 渲染） |
| 浏览器族 | login / captcha / pick / takeover | 内嵌浏览器 + 提示 + 完成按钮 |

- 一族一套控件，8 种类型全覆盖，不为单类型开发专用控件；
- 副作用节点 confirm 固定提示"重复执行可能产生重复效果"；
- login 完成后的登录态捕获与加密落库归 M04/M05，本模块仅呈现。

### 3.6 任务详情

- 步骤视图：DAG 节点状态 + 各节点实际生效积木版本（lock `effective`）；
- 交互历史：interactions 记录只读回放；
- 错误呈现：错误堆栈 + failure_class 标签（错误码→failure_class 映射表由 M09 维护，架构 §8.2）+ 修复建议（失败模式库匹配，M15 只读）；
- 日志导出：统一 JSONL，经脱敏管道（架构 §6.8：内置模式 + 明文集精确替换）后导出。

### 3.7 设置

- 账户、通知、数据清理（含交互记录留存策略说明与清理动作）、版本更新（electron-updater）、关于；
- **运行上报开关**（架构 §9.2）：开启——运行结果（不含页面内容）参与用户运行成功率与健康分统计；关闭——不参与统计，其退款判据锚点为激活校验时间戳；开关默认值随隐私政策披露方案定，TBD（模块细化时定）。


## 4. 数据模型（客户端 SQLite，架构 §12.3 子集）

```text
library(app_id, version, purchased_at, maintenance_until, activated_at)
tasks / task_steps / artifacts      # M05 执行器写入，本模块读写展示
interactions(id, task_id, family, type, payload_json, state, expires_at)
settings(key, value)                # 含运行上报开关
```


## 5. 接口

- 消费 M10：商店列表/详情（trust_fields）、下单支付、激活校验上报、文字评价、通知拉取；
- 消费 M11：健康状态与失效通知（My Library 与通知中心呈现）；
- 上报 M11：`{app, effective_block_versions, run_result, failure_class, env_class}`（脱敏后，不含页面内容）；
- IPC（经 M05 sidecar）：`task.submit / task.cancel / task.defer`、状态订阅；交互应答经 M16：`interact.resume / interact.extend`。


## 6. 依赖与被依赖

- 依赖：M01（客户端框架与更新）、M04（模型配置引导/凭证状态）、M05（执行与 grants）、M10（商品/订单/信任字段）、M11（健康状态与失效通知）、M15（修复建议）、M16（交互协议）。
- 被依赖：M10（买家触点、激活数据回流）、M11（运行上报来源）、M16（用户运行中心宿主）。


## 7. 验收标准

1. 信任字段 v2 全字段渲染 E2E 断言：分列通过率均带样本量、"数据不足"分支、C1 标注、页脚声明原文一字不差；
2. 高变更/受防护应用 best-effort 警示位于首屏显著位置且不可折叠；
3. 未勾选数字商品确认时支付不可用；激活校验时间戳落库并上报 M10；
4. 授权页按站点渲染操作清单与账号风险告知一行；未授权运行被权限层拒绝（与 M05 联测）；
5. 交互超时 → suspended → 72h 内"稍后继续"成功恢复；超窗 → cancelled；浏览器族挂起提示 2h 会话关闭；
6. 两族控件覆盖 8 种交互类型；副作用 confirm 显示固定提示；半执行态恢复显示核查提示；
7. 日志导出文件经明文集注入测试验证脱敏命中；
8. 关闭运行上报后无上报网络请求，退款判据说明文案同步更新；
9. 文字评价可提交与展示，界面无五星评分入口；
10. 商店卡片与列表页的精简字段同样带样本量与认证等级（列表页抽查断言）。
