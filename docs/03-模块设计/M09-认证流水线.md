# M09 认证流水线 模块设计 v1.0

> **职责**：把"可靠性可测量"落成可运行的系统——积木/应用版本发布前的统计认证（纯真实运行口径）、创作者本机认证（C1）、抽查重测、认证报告与详情页初始可靠性分。
>
> **上游依据**：`01-产品文档.md` v14.2 §9；`02-技术架构.md` v8.2 §4。
>
> **状态**：起草（2026-10-14）。**阶段 1 地基模块。**


## 1. 职责与边界

| IN（本模块负责） | OUT（不属于本模块） |
|---|---|
| 认证调度（队列、限频、批次礼仪） | 积木内容静态检查（M07 Quality Skill） |
| C2 平台沙箱真实运行认证 | 上架审核决策（M10 审核清单） |
| C1 本机认证器（客户端模块） | 健康系统持续检测（M11） |
| C1 抽查重测与处置建议 | 保障金池账务（M10 结算） |
| golden 回放回归（复用 M07 回放器，经 `replay.run(trace_ref, params, mode=golden)` 唯一入口） | 录制与参数化（M07/M02） |
| 认证报告生成与 `certification_runs` 写入 | 详情页渲染（M03） |
| 应用级整链验证（分级路由） | — |

**核心不变量**：
1. `live_pass_rate` 只能来自真实运行，回放结果只能进 `regression_pass_rate`，两字段在存储、展示、API 三层不得混算；
2. 认证批次礼仪不可配置绕过（≤20 次真实访问、跨 ≥48h、单会话、**限频**）；
3. C1 凭证不出本机——本模块的全部 C1 代码运行在创作者设备上，服务端只见签名报告。

## 3. 关键流程

### 3.1 C2 积木认证（无登录，标准/中变更站点）

```text
提交版本 → CertScheduler 排期（批次礼仪校验）
  → 环境矩阵：≥2 OS × ≥2 时段（容器镜像池）
  → 每次运行：真实访问目标站点 → 步骤结果 + 归因采集
  → N≥20 完成 → live_pass_rate 计算 → 阈值判定（§PRD 9.3）
  → golden 回放回归（同批执行，写 regression_pass_rate）
  → 认证报告落库 → 通知提交者
```

认证中交互路由：遇 login → 自动转 C1 流程（重排期）；遇 confirm → 使用 `default_response` 认证响应脚本，未声明 → 标记"部分认证"（不可上架）；副作用积木 → 响应脚本自动执行两遍验证幂等；验证码 → 该次计失败（captcha）。

### 3.2 C1 积木认证（含登录，创作者本机）

```text
设备注册（一次性）：客户端生成 ed25519 密钥对 → 公钥+设备指纹注册到服务端
  ↓
提交认证 → 服务端下发 nonce + 参数集（认证规范生成，含随机化输入）
  ↓
本机 N≥20 真实运行（本机环境 × ≥2 时段；认证会话与日常凭证隔离）
  ↓
报告生成：结构化步骤结果 + 失败归因 + 环境指纹（不含页面内容）
  ↓
设备密钥签名（覆盖 nonce + 报告哈希）→ 上传
  ↓
服务端初验（签名/nonce/时长合理性）→ 上架资格初审通过
  → 后续由抽查重测 + 用户上报滚动修正（信任模型见架构 §4.3）
```

**golden 接收校验（服务端）**：C1 golden 子集上传通道强制值脱敏校验（占位符规范，含原始值拒收）；存储边界——**仅存认证服务端**，不进入任何分发通道（M10 打包/签名剔除 `tests/golden/` 为第二道防线，验收联测）。

### 3.3 应用级整链验证（分级路由）

| 应用构成 | 执行位置 | 说明 |
|---|---|---|
| 全 C2 积木 | 平台沙箱整链 1 次 | 免费额度 |
| 含 C1 积木 | 创作者本机整链 1 次 | 复用 LocalCertifier，签名报告 |

### 3.4 抽查重测

```text
抽样：每 10 份 C1 报告至少 1 份（周期性滚动）
  → SpotcheckService 生成重测任务（随机参数 + 指定时间窗）
  → 创作者客户端接受任务 → LocalCertifier 执行 → 实时流式上报逐步结果
  → 服务端比对：步骤序列/时序分布/网络行为形状 vs 原报告
  → 不符 → attestation_invalid → 积木版本下架 + 保障金池流程
            + 引用应用标记"积木维护中"（管理后台 M12 工作台处置）
  → 超时未响应重测（14 天）→ 同"创作者超期未响应"归因档
```

### 3.5 patch 回归（轻量，区别于版本认证）

声明式 patch 发布前：golden 回放回归（沙箱 mock / C1 本机）+ smoke；**不重跑 N≥20**，不更新 live_pass_rate（口径不变：live 只来自版本级真实运行批次）。


## 4. 数据模型

```text
certification_runs(
  id, subject_type,        # block / app_version
  subject_id, version,
  level,                   # C1 / C2 / chain（应用整链）
  n, pass,
  live_pass_rate, regression_pass_rate,
  env_fingerprint_json,    # OS/浏览器版本/网络类型/时段/矩阵槽位
  fail_json,               # 逐步失败 + failure_class 归因
  attestation_sig,         # C1 时非空
  batch_id,                # 批次礼仪审计
  started_at, finished_at, verdict   # pass / below_threshold / partial / rejected
)

spotcheck_tasks(
  id, report_id, params_json, window_start, window_end,
  status,                  # pending / accepted / streaming / done / mismatch / timeout
  compare_json, created_at
)

client_devices(            # C1 设备注册
  id, creator_id, public_key, device_fp, registered_at, revoked_at
)
```

attestation 载荷：`{nonce, report_hash, env_fingerprint, client_version, ts}`，ed25519(client_device_key) 签名；nonce 一次性、5 分钟有效。


## 5. 接口

**服务端 REST（/api/v1）**：
- `POST /certifications`（提交：subject/version/level）
- `POST /certifications/devices`（C1 设备注册：公钥 + 设备指纹，绑定创作者账号）
- `GET /certifications/{id}`（报告：live/regression 分列、环境、归因、verdict）
- `GET /blocks/{name}/versions/{v}/reliability`（详情页初始分；**仅 live 口径，不含 regression_pass_rate**；强制携带 C1 标注字段"创作者环境实测，平台抽查复核"；带 N 与时间窗）
- `POST /certifications/nonce`（C1 取 nonce——**nonce 端点全局唯一属主**，M11 创作者触发检测复用）
- `POST /certifications/{id}/report`（C1 签名报告上传，幂等；含 golden 子集脱敏校验）
- `GET /certifications/spotcheck/tasks` / `POST /certifications/spotcheck/tasks/{id}/accept`（创作者侧抽查任务拉取与接受）
- `WS /certifications/{id}/stream`（重测流式上报）

**客户端模块 API（LocalCertifier）**：
- `certify(block_ref, n, params) → report`（阻塞式，进度回调）
- `accept_spotcheck(task) → stream`
- 设备注册与密钥管理（safeStorage 保护私钥）


## 6. 防作弊设计（威胁 → 对策）

| 威胁 | 对策 |
|---|---|
| 报告转储/重放 | nonce 一次性 + 报告哈希签名 + 时间窗 |
| 伪造运行（不真跑） | 结构指纹比对（步骤序列/时序分布/网络行为形状）；时长下限校验 |
| 挑最容易的参数集 | 参数由服务端随机生成下发，不接受客户端自选 |
| 多设备分流刷认证 | 设备注册绑定创作者账号；同账号设备数上限 |
| 环境造假（伪装 OS） | 环境指纹交叉校验（客户端多源采集）；异常环境标记人工复核 |
| 长期漂移（先真后假） | 抽查滚动 + 用户上报滚动修正展示分 |

诚实边界：以上机制**提高造假成本，不消除造假**——最终修正依赖用户运行上报（PRD §10.2），本模块在详情页强制标注"创作者环境实测，平台抽查复核"。


## 7. 依赖与被依赖

- 依赖：M05（sidecar 运行环境与出口代理）、M07（测试夹具/golden 回放器/认证响应脚本）、M06（沙箱浏览器执行）、M04（认证会话管理）、M10（Registry/提交入口）。
- 被依赖：M10（上架门槛消费 verdict）、M03（详情页初始分 API）、M11（certification_runs 作为健康初始值）、M12（抽查工作台）、M15（可靠性主数据集）。


## 8. 验收标准

1. C2 路径：批次跨度 ≥48h（礼仪下限）且提交到报告 ≤72h（含批次与开销）；live/regression 分列且不可混算（存储层约束测试）；
2. C1 路径：设备注册→nonce→本机 20 次→签名报告→初验 全流程在客户端单机跑通；认证会话即焚有测试证明；
3. 抽查：一次完整的重测任务下发-执行-比对-处置链路（含 mismatch 分支）可演示；
4. 批次礼仪：限频与 ≤20 次上限在调度器层强制（配置绕过测试不通过）；
5. 报告口径：任意 API/页面取到的通过率均带 N 与时间窗（无样本量展示为"数据不足"）；
6. 阶段 1 gate 联动：平台自营 20-30 个积木全部持有 C1/C2 认证报告；
7. golden 边界：上传通道含原始值的 golden 被拒收；认证服务端 golden 存储不出现在任何分发产物中（与 M10 打包剔除联测）。
