# M11 健康系统（积木级） 模块设计 v1.0

> **职责**：上架后的持续可靠性度量——礼仪红线内的分级检测调度、用户运行上报聚合、分列健康分、失效归因与自修复触发；一次修复，全体引用应用恢复。
>
> **上游依据**：`02-技术架构.md` v8.1 §9（归因矩阵见 §8.2，修复链见 §3.3）；`01-产品文档.md` v14.1 §10。
>
> **状态**：起草（2026-10-14）。**阶段 2 交付（买家闭环）。**


## 1. 职责与边界

| IN（本模块负责） | OUT（不属于本模块） |
|---|---|
| 检测调度器（分级频率/成本降频/免费 ×0.5） | 版本发布前认证批次（M09） |
| 服务端沙箱全量检测（无登录·标准/中变更） | 自修复候选生成与 golden 回归（M15） |
| 低频公开页探活（无登录·高变更/受防护） | 退款账务与归因档处置（M10） |
| 含登录积木创作者触发检测入口 | 仲裁与归因复核工作台（M12） |
| 用户运行上报管道与聚合 | 上报 SDK 宿主与设置 UI（M01/M03） |
| 积木/应用健康分（分列口径）与详情页 API | 页面结构特征库/失败模式库维护（M15 二库） |
| user-side 归因矩阵执行、unknown>30% 告警 | — |
| 声明式自修复触发链（→M15）与曝光微调因子 | — |

**核心不变量**：
1. 检测频率红线（D7）：**含登录积木无服务端定时检测**（创作者触发 + 用户上报聚合）；无登录高变更/受防护站点**无持续定时全流程检测**（仅 ≤72h 一次公开页探活）；
2. 健康分**分列不可合成**：认证通过率（初始，纯真实运行口径）与用户运行成功率（滚动）分列展示、均带样本量；**通过率类字段对复合积木与应用均不合成**（PRD §9.5）；**应用级健康分**按 PRD §10.2 聚合（应用级汇总 + 积木明细同时给出）；复合积木健康只展示内层明细；
3. user-side 归因不计积木分（判定矩阵见架构 §8.2）；security 类单列，不进成功率分母；
4. `health_checks` 挂 `block_version_id`（积木版本，非应用；架构 §9.1 原文作 component_version_id，按 Block 统一术语对齐 M10 §4 `block_versions`）；运行上报与聚合按 lock `effective` 版本归因；
5. 上报载荷白名单固定，**不含页面内容**；关闭上报的账号不参与统计，其退款判据改为激活校验时间戳（架构 §10.2）。

## 3. 检测分级表（架构 §9.1 全表）

| 积木类型 | 检测方式 | 频率 |
|---|---|---|
| 无登录（标准/中变更） | 服务端沙箱全量 | 默认 24h，成本超阈值自动降频 |
| 无登录（高变更/受防护） | 低频公开页探活 | ≤72h 一次，无持续定时全流程检测 |
| 含登录 | 创作者手动触发检测 + 用户运行上报聚合 | 无服务端定时检测 |
| 含交互 | 使用默认响应或跳过，标记"部分检测" | 跟随所属积木 |
| 免费应用 | 同上各档 ×0.5 频率 | 降频 |

- 检测礼仪默认强制（PRD §7.3）：仅公开页、低频、单会话、尊重 robots 协议、UA 与真实浏览器一致、仅对应用/积木声明的目标域名执行、频次上限；
- 检测中命中验证码 → 该次计失败（归因 captcha），不以自动方式响应；
- **免费系数语义**：排期按"应用 × 积木引用对"计算；同一积木被免费与付费应用同时引用时，取两档中**较高频率**（付费档）——免费降频不拉低付费引用的检测频率。


## 4. 关键流程

### 4.1 定时检测（无登录两档）

```text
HealthScheduler 按 component_version_id 排期（基础频率 × 免费 ×0.5 × 成本降频）
  → 沙箱全量（标准/中变更）或公开页探活（高变更/受防护）
  → 结果 + failure_class 归因 → health_checks 落库
  → ScoreAggregator 聚合 → 异常 → 自修复触发（→M15）/ 失效流程（→M10）
```

### 4.2 创作者触发检测（含登录档）

- 入口：创作者在客户端对含登录积木发起检测，复用 M09 本机认证器的执行与签名上报机制（凭证不出本机，与架构 §3.3 修复链同型）；
- 服务端只接收签名结果并聚合；**调度器对含登录积木不产生任何定时任务**（红线断言，见验收 1）。


### 4.3 用户运行上报管道与归因

- 客户端上报字段：`{app, effective_block_versions, run_result, failure_class, env_class}`——白名单固定，不含页面内容；
- 隐私政策披露，设置可关闭；**关闭上报的账号不参与统计**，其退款判据改为激活校验时间戳；
- 归因执行（架构 §8.2）：`auth_expired ∧ env_class=account`、`network ∧ env_class=network` → user-side，不计积木分；其余组合计站点/积木侧；security 类（egress_denied 等）单列，不进成功率分母，记安全事件。

### 4.4 健康分计算与展示口径

- **积木健康** = 认证通过率（初始，纯真实运行口径，引自 M09 certification_runs）+ 用户运行成功率（滚动），**分列展示，均带样本量与时间窗**；
- 用户运行成功率最小样本 30，不足显示"数据不足"，不显示分数；无样本量不得展示；
- **应用健康** = 工作流上各积木健康的聚合（按 lock `effective` 版本归因；应用级汇总分 + 积木明细同时给出，**通过率类字段不合成**——PRD §9.5/§10.2；积木修复后自动恢复，无需逐应用修复）；
- 复合积木健康 = 内层积木健康明细，不合成单一分值；
- 修复响应时效不进健康分，仅作曝光微调因子；
- 详情页固定注明："健康评分覆盖公开页检测；含登录态与交互的流程依赖用户运行上报。"


### 4.5 告警与联动

- unknown 归因占比 >30% → 触发告警（服务端，月窗口）；
- 检测/上报发现积木异常 → 声明式自修复触发链：候选生成（M15）→ golden 回放回归（C2 沙箱 mock 网络存根 / C1 本机认证器回归）→ 创作者确认 → 签名发布 patch（M10）→ 灰度自动更新 → 引用应用恢复；
- 失效归因结果输出 M10（退款判据、归因档处置）与 M12（仲裁/复核）。


## 5. 数据模型

```text
health_schedules( id, block_version_id,
  tier,                     # 分级档位（检测分级表四档）
  base_frequency, cost_throttled, free_factor, next_run_at )

health_checks(              # 挂 block_version_id（积木版本，非应用）
  id, block_version_id,
  check_kind,               # sandbox_full / public_probe / creator_triggered
  result, failure_class, env_class,
  started_at, finished_at )

run_reports(                # 用户运行上报（白名单校验后落库）
  id, user_id, app_id,
  effective_block_versions_json,   # 运行时实际生效版本（归因键）
  run_result, failure_class, env_class,
  reported_at )

health_reports(             # 聚合快照（分列，供详情页/曝光微调）
  id, block_version_id,
  cert_pass_rate, cert_samples,     # 初始：纯真实运行（引自 certification_runs）
  user_pass_rate, user_samples,     # 滚动：<30 → "数据不足"
  unknown_ratio,
  window_start, window_end, computed_at )
```


## 6. 接口

**服务端 REST（/api/v1）**：
- `POST /health/run-reports`（运行上报：五字段白名单；批量、幂等）；
- `POST /health/creator-checks`（含登录积木触发检测：签名结果上报；**挑战响应复用 M09 机制**——nonce 端点全局唯一属主为 M09 `POST /certifications/nonce`，设备密钥复用 client_devices，不另建挑战响应）；
- `GET /blocks/{name}/versions/{v}/health`（分列健康分 + 样本量 + 时间窗；数据不足规则）；
- `GET /apps/{id}/health`（应用级健康汇总分 + 引用积木明细；通过率类字段不合成）；
- 内部：unknown>30% 告警事件、曝光微调因子查询（运营消费）、失效归因事件（→M10/M12）。

**客户端挂点**：运行上报 SDK（M01 集成，设置可关闭）；创作者触发检测入口（M02 界面，复用 LocalCertifier）。


## 7. 依赖与被依赖

- 依赖：M09（certification_runs 初始通过率、沙箱与本机认证器机制）、M05/M06（沙箱运行环境与浏览器执行）、M10（Registry 版本元数据、patch 发布与灰度通道）、M15（自修复承接、失败模式库回填）。
- 被依赖：M10（失效判定与退款判据、归因档输入）、M03（详情页健康展示）、M12（仲裁与归因复核）、M15（自修复触发源）。


## 8. 验收标准

1. 红线断言：调度器对含登录积木不产生定时任务；无登录高变更/受防护积木仅有 ≤72h 公开页探活，无持续定时全流程检测；
2. 免费 ×0.5：同一积木被免费应用引用时检测排期频率减半（排期快照测试）；
3. 归因矩阵：auth_expired×account、network×network → user-side 不计积木分；security 类不进成功率分母（构造上报用例验证）；
4. 展示口径：用户样本 <30 → "数据不足"；所有比率带样本量与时间窗；复合积木/应用无合成单一通过率；
5. 版本归因：patch 更新（1.2.0 → 1.2.3）后的运行按 lock effective 版本计入新版本（用例验证）；
6. 上报开关：关闭上报账号的运行不进入任何聚合；其订单退款判据仍为激活校验时间戳（与 M10 联测）；
7. 隐私：上报载荷 schema 白名单拒绝额外字段；抽样审计不含页面内容；
8. 告警：unknown 归因占比 >30%（月窗口）触发告警事件；
9. 触发链：一次检测异常 → M15 候选 → 回归 → 创作者确认 → M10 签名灰度 → 引用应用健康恢复，端到端可演示。
