# M14 积木市场 模块设计 v0.5（骨架）

> **职责**：积木作者生态的供给与交易侧——第三方积木（站点 / 通用 / 复合）上架公开市场、认证门槛、引用量结算与治理框架。**本文档是 PRD §13.2"阶段 4 前单独设计清单"的承载文档**：已确定原则不再议，未确定项逐条立项决策。
>
> **上游依据**：`01-产品文档.md` v14.1 §1、§3.2/§3.3、§8.1、§13.2、§15；`02-技术架构.md` v8.1 §2.5、§3.1、§10、§12.1；`04-评审报告-2026-10-13.md`（"第一市场未验证就建第二市场"）。
>
> **状态**：骨架（2026-10-14），**后置阶段 4**。


## 1. 定位与开放前提

**定位**：积木（Block）的公开交易市场（`distribution: public`），服务积木作者（技术角色，PRD §8.1）。应用市场（M10）先验证"实测通过率可卖钱"，买家闭环成立后才开放积木供给侧。

**开放前提（全部满足才投入实现）**：

1. 阶段 2 gate 已过：应用市场已验证（30 天退款率 <5% 且首跑成功率 ≥80%）——顺序原则：买家不买单，创作者生态不开放投入（PRD §15 注）；
2. 阶段 3 gate 已过：创作成功率 ≥60%，保障金池全运行；
3. **启动条件不含供给指标**——供给必须先有市场才存在（循环依赖澄清）："积木作者供给 ≥ 平台自营 50%" 是本模块的**阶段 4 出口度量**（成功标准，PRD §15 阶段 4 gate），不是启动前置；
4. §3 决策清单五项全部完成产品决策并落入本模块 v1.0。

## 1.5 骨架期验收

- 前置条件可判定：本节四项均引用可执行的 gate 锚点（PRD §15 / 本模块决策登记），无循环依赖；
- 决策清单可追踪：D1-D5 各有"待产品决策"状态位与决策记录落点（决策后回填本模块 v1.0）。


## 2. 已确定的原则（不需再决策）

| # | 原则 | 依据 |
|---|---|---|
| 1 | **认证要求同原子积木**：公开市场仅接受 C1/C2 积木，C0 不可上架；认证走 M09 同一流水线（真实运行 N≥20、环境矩阵、C1 抽查每 10 份至少 1 份）；积木认证成本平台承担 | PRD §3.2/§9.1 |
| 2 | **app-bound 与公开市场分离**：复合积木默认 `distribution: app-bound`（随应用分发的受保护实体：平台签名、买家可解析、作者不可删除被引用版本、不计入积木市场）；主动上架公开市场（public）为阶段 4 能力；change_kind=composite 仅整体重发布、无自动更新通道；含 C0 内层的复合积木不可认证、不可上架；可靠性展示不合成单一通过率 | 架构 §2.5 |
| 3 | **抽成 30% 框架**：积木作者按被认证应用引用量分成；应用侧平台 30% / 创作者 70% 框架不变；保障金池初始资金由平台注资（30% 抽成的风险对价组成部分）不变；结算台账只增不改 + 冲正分录 | PRD §13.2、架构 §10.3 |
| 4 | **健康与修复义务同等**：第三方积木纳入积木级健康系统（M11）；声明式 patch 自动更新通道仅 change_kind=declarative 且权限集不扩大 | PRD §10、架构 §3.2 |
| 5 | **用户承诺不变**：引用第三方积木的应用同受 12 个月维护期与失效退款规则覆盖；赔付资金来源随 §3 D2/D4 决策确定 | PRD §13.1/§13.2 |
| 6 | **合规与治理同等**：站点合规声明、检测礼仪、依赖白名单、签名分发、发布审核清单（PRD §9.4）对第三方积木全部适用；违规处置走 `delisted`（平台下架） | PRD §16、架构 §10.1 |


## 3. 阶段 4 前必须单独立项决策的清单

> 以下各项均为**待产品决策**（TBD，阶段 4 前定）；本节只列问题与选项，不预设结论。

### D1 积木定价机制

- **问题**：积木作为中间供给物如何计价与呈现——买家购买应用时积木成本如何计入价格与信任字段；
- **选项**：a) 积木免费上架，仅按被认证应用引用量分成；b) 积木作者定价，按引用计费或买断；c) 平台分级指导价；
- **待产品决策**。

### D2 维护义务与保证金对齐

- **问题**：积木作者是否缴纳保证金、释放节奏是否对齐应用侧（20% 分 6 期双月释放、超 14 天未响应转入平台保障金池）；积木失效波及全部引用应用，责任被放大；
- **选项**：a) 完全对齐应用侧条款；b) 按积木分成收益分档设保证金；c) 不设保证金，以分成暂停与账号信用处置替代；
- **待产品决策**。

### D3 三级分成（平台 / 应用创作者 / 积木作者）

- **问题**：一笔应用收入在既有 30%/70% 之外，积木作者份额从何处切分、按什么口径（引用次数 / 引用时长 / 运行量）计；
- **选项**：a) 平台 30% 份额内切分积木作者份额；b) 创作者 70% 份额内按引用占比切分；c) 混合（自营 / 第三方积木差异处理）；
- **待产品决策**。

### D4 失效归因新增"第三方积木作者缺陷"档

- **问题**：现有失效归因分级（站点变更非过错 / 创作者超 14 天未响应 / 平台积木缺陷 / 废弃）未覆盖第三方积木作者过错；需定义罚则、保障金池资金来源、引用应用处置（"积木维护中"标记）；
- **选项**：a) 对齐"创作者超期未响应"档（转入平台保障金池）；b) 单设轻量档（分成暂停 + 修复义务，不转入保障金池，赔付走平台保障金池）；c) 按作者信用等级分档；
- **待产品决策**。

### D5 源码 IP 与转售约束

- **问题**：客户端按需拉取签名积木包并在本地缓存最后可用版本——公开市场积木对应用创作者 / 买家是否可见源码；反编译、转售、二次分发与衍生积木的约束；license 分级；
- **选项**：a) 分发仅含受保护形态 + 平台签名；b) 源码可见 + 创作者协议负面清单约束；c) license 分级由积木作者选择；
- **待产品决策**。
