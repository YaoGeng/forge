## 1. 定位与开放前提

**定位**：积木（Block）的公开交易市场（`distribution: public`），服务积木作者（技术角色，PRD §8.1）。应用市场（M10）先验证"实测通过率可卖钱"，买家闭环成立后才开放积木供给侧。M14 是 M10 Registry 的**市场层扩展**，不另建第二套 Registry——所有积木身份、版本、签名、分发通道仍归属 M10 现有实现面（§3）。

**开放前提（全部满足才投入对应阶段实现）**：

1. 阶段 2 gate 已过：MS-2 判定式 = 每个上架应用首跑成功率 ≥80% 且 n≥5 个不同真实注册用户（docs/05 附录 A.5 修订 / `web_admin.py` GATE_TEXT）。**现状（2026-10-31，试点面板口径）**：hn_weekly 85.7%（n=7）达标；price_watch n=2 样本不足——**gate 未达，本模块阶段 B/C 均不投入**；
2. 阶段 3 gate 现状：创作成功率 ≥60% 未达——D-4 覆盖率实验与 R2 复判均 fail（docs/06 里程碑 2026-10-25 登记），已明确"**不进创作者开放投入**、不再起第三轮收窄重做"。M14 的 B 阶段（积木作者投稿面）是**积木作者角色**的投入，不等同于应用创作者九步流开放；其投入门槛在 D-5' 达标之上仍需人工决策点确认（§10 B-gate）；
3. **启动条件不含供给指标**——供给必须先有市场才存在（循环依赖澄清，骨架原文保留）："积木作者供给 ≥ 平台自营 50%" 是本模块的**阶段 4 出口度量**（PRD §15 阶段 4 gate），不是启动前置；
4. §3 决策清单五项（D6.1-D6.5）已于 2026-10-14 完成产品决策并回填（docs/05 附录 A.6，T-doc.3 已同步 PRD v14.2）——**该前提已满足**；
5. **收款现状约束（v1.0 新增）**：MS-2 S-1 裁定收款整体顺延（订单/支付/退款冲正/保障金池/结算全部不在 MS-2，无支付通道）——积木买断初期只能以**「记账沙箱」**运行：台账分录真实记账、资金结算后置（§5.3，待决策 MD-1）。

**开放前提小结**：前提 4 已满足；前提 5 决定了 A 阶段的沙箱形态；前提 1/2 未满足，A 阶段（平台内部基建，不面向创作者）可先投入，B/C 显式挂 gate。

### 4.3 上架状态机

```text
draft → submitted → certifying → in_review → listed
certifying verdict 分流（M10 §3.1 映射对齐）：
  pass → in_review
  below_threshold / partial → rejected（附认证报告）→ 修订 → submitted（重提回边）
  rejected（认证执行失败：批次中断/环境不可用）→ submitted（重排期回边，
      不计失败、不要求修订——M10 §3.1 同口径）
in_review → rejected（A7 reject：审核清单不通过）→ 修订 → submitted（重提回边）
listed → delisted（平台下架：D6.4 缺陷档 / 治理违规 / 安全事件）
listed → deprecated（作者废弃；提前 30 天通知，已购保留最后版本本地使用权）
delisted → listed（整改复核通过后的唯一回边，需管理面显式 relist）
```

- 命名沿用骨架与 D6.4：市场下架态一律 `delisted`（与任务挂起态 `suspended` 严格区分；结算分录的 `suspended` 是**分录状态**不是上架态）；应用侧 M10 状态机终态为 `published`，积木市场为 `listed`，二者并存不互斥（不同域）；
- certifying 委托 M09 执行（submit 时服务端代开认证 run），verdict 回写后流转，映射规则同 M10 §3.1；
- in_review 审核清单 = 原则 6 展开（认证报告核验 + 站点合规声明 + AI 内容标识 + confirm 覆盖 + 权限最小化 + lint 报告）；
- 阶段 A 自营块挂接：26 个自营块（owner_id="platform"）由管理面批量初始化为 listed（免认证重跑——认证报告已在库，M10 §3.1 状态机对自营同样适用但历史 run 视为已核验）。

### 4.4 买断权益与引用校验（行为扩展，标注「新增校验」）

- **引用校验**：`registry.py create_version` 既有"未认证积木拒绝入组合"检查旁，新增一条——组合内引用 owner≠"platform" 的积木时，请求用户须持有对应 `block_entitlements`；无权益 → 422，detail 文案风格对齐既有"含未认证积木 …先完成 C1/C2 认证并注册后再入组合"；
- **免费取用**：免费积木"直接取用"（D6.3）的落地形态为 0 元买断（MD-3 推荐），即同走 purchase 通道落权益，保证引用校验单判据（查 entitlement 一张表）；
- 自营积木（owner="platform"）不设引用门槛（现状不变）；付费买断后涨价不影响既有权益（amount_cents 快照）；
- 权益转移/转售：禁止（D6.5 负面清单同步覆盖权益转售）。


## 5. 交易与台账（买断分录结构 + 记账沙箱）

### 5.1 交易流程

```text
浏览（market 目录/详情，信任字段铁律）→ purchase（登录，幂等）
  → 0 元：直接落 order(paid, 0) + entitlement + 0 元分录组（MD-3）
  → 付费：落 order(paid, ¥P) + entitlement + 三段分录（§5.2）——沙箱期无资金流
  → pkg 下载（gated：查 entitlement，§8 A5）
  → Creator Center 组合引用（registry 新增校验，§4.4）
```

- 无 24h 全退、无争议期自动退款——积木买断退款仅经归因冲正路径（D6.4 处置链），争议仲裁走 M12 工作台（人工触发冲正）；
- 同一用户重复 purchase 同一积木 → 幂等返回既有 order+entitlement（`X-Idempotent-Replay: true`，对齐 `acquire_entitlement` 惯例）。

### 5.2 买断分录结构（D6.3 终稿的台账化）

```text
付费买断 ¥P（P>0，以分记账；30% 取整规则：platform_share = P*30//100，author=P-platform_share）
  L1 buyer_pay         amount = -P   （买方支出方向）
  L2 platform_share    amount = +30% （平台）
  L3 author_settleable amount = +70%（积木作者；status=pending）
  约束：单笔订单三段分录代数和 = 0（复式守恒，验收锚点 §12-5）
退款/赔付（冲正，仅归因触发）：
  L4 对 L1/L2/L3 各生成负向 reversal（reverses_entry_id 指回原分录，attribution_id 关联归因）
  L5 pool_payout：买家赔付出账分录（资金来源=保障金池；池侧以 pool_inject 平台注资分录记账）
```

- **台账不变量（只增不改的精确口径）**：`amount_cents`、`entry_kind`、关联字段（order_id / reverses_entry_id / attribution_id）**只增不改**，任何金额修正以冲正实现（对齐 M10 §1 不变量 1）；`status` 为唯一受控流转字段（pending→available→suspended⇄available；`written_off` 仅由 MD-1 决策的沙箱清账流程使用），每次流转由事件驱动并留 credit_events / 结算事件溯源；
- **沙箱期语义**：`author_settleable` 无提现出口（不建 withdrawals / settlement_accounts——M10 §4 的提现实名体系随收款接入）；沙箱台账的可用余额查询即 §8 A6 的响应主体；
- 分成暂停（D6.2 信用处置）：`credit_events` 落 `share_suspend` 后，该作者在途 `author_settleable` 分录 status → suspended、新买断分录 L3 直接以 suspended 入账；`share_resume` 后原分录 status 流转回 available（金额不动，流转留 credit_events 溯源）；
- 冲正与池账守恒：冲正组（对 L1/L2/L3 的三条负向 reversal）代数和 = 0 且与原分录组镜像；`pool_payout` 累计出账 ≤ `pool_inject` 累计注资（池账平衡）；
- 与 M10 结算域的命名映射（MD-1 并入路径，防返工）：`author_settleable ↔ M10 creator_settleable`；`pool_inject`/`pool_payout ↔ M10 guarantee_pool_ledger 的 platform_inject`/`payout`（transfer_in/platform_cover 沙箱期不产生）；`buyer_pay` 为 M14 私有段（并入时映射为订单侧流水）。

### 5.3 记账沙箱（MS-2 收款顺延的现实约束）

**事实**：无支付通道（S-1），真实收款无法发生。沙箱设计：

- 台账分录**真实记账**（金额、守恒、冲正、归因全部按 §5.2 真实口径执行），仅"资金进出"一个维度后置——沙箱数据在收款接入时**可全额对账兑付**（这是沙箱不是假账的判据）；
- 付费轨是否随沙箱开放 → 待决策 MD-1（选项含"沙箱期关闭付费轨只留免费轨"）；
- 保障金池：池台账以 `pool_inject` / `pool_payout` 分录记账（平台注资金额按 D6.2 口径登记），真实资金池随收款接入实体化。


## 6. 受保护分发（源码不可见的落地形态，待决策 MD-2）

**D6.5 终稿**：源码不可见——分发仅含受保护形态 + 平台签名；反编译/转售/二次分发与衍生积木约束写入创作者协议负面清单；license 单一默认条款，不分级。

**诚实边界（先写死，防过度承诺）**：积木在买家本机运行（M05 sidecar），执行时刻代码必然落地客户端——**任何客户端分发机制都做不到密码学意义的"不可反编译"**。D6.5 的可执行口径 = ①不进公开包库（bundle 上传通道仅投稿者/平台可达）②下载 gated（无权益 403）③平台签名可溯源（泄露可定位订单）④协议负面清单 ⑤（选型加固）技术性抬高逆向成本。本节选项均在此边界内比较。

| 选项 | 机制 | 取舍 |
|---|---|---|
| a) 加密包 | 演进既有 zip+ed25519 体系：服务器侧对 zip 做对称加密（包密钥随 `block_entitlements` 派生下发），运行器解包后即焚明文缓存 | 最接近"受保护形态"字面；需动 packages.py 签名链与运行器解包；本地缓存仍可被 dump；实现成本高 |
| b) 服务器侧按 license 解包 | 密文仅传输，运行器安装时向服务端请求**按权益签发的解包容器**，不落密钥 | 权益校验强（每次安装在线）；牺牲离线安装与既有 TOFU/本地缓存形态（M03 离线可跑承诺冲突）；服务端成为分发热点 |
| c) 明文 zip + license 校验清单 | 维持现有 zip 形态（`code_bundle` + `_validate_bundle` + ed25519 签名头），包内新增 `META/license.json`（license 模板 id、买断 order_no、签名覆盖）+ 下载 gated | 零新增密码学机制、可审计（order_no 溯源泄露源）、离线友好；"保护"主要靠 gated + 协议，技术防护最弱 |

- **推荐**：阶段 A/B 采用 **c**（最小改动、与既有实现面零冲突、先跑通交易闭环），收款接入时升级 **a**（作为 MS-2 顺延清单"强签名与密钥治理"的同批项）；
- **回退链**：c 被评审判定保护不足 → a（加密包）→ b（服务器解包，需先豁离线承诺，属产品层变更，须人工拍板）；
- **状态：待决策 MD-2**。本文档后续章节按 c 展开接口（A5 端点响应含 license 清单），选 a/b 时仅 A5 响应体与运行器解包侧变化，契约骨架不变。


## 7. 健康纳入与治理处置

### 7.1 健康纳入（原则 4 落地）

- 市场信任字段（A2 响应）= `certification_level` + reliability_json（live 口径带 n 与时间窗、C1 标注）+ `health.grade()` 三档 + price + license 摘要；分列铁律与"数据不足"规则逐字沿用（§3.1 信任字段锚点）；
- 复合积木（若 MD-4 收录）：只展示内层积木健康明细，不合成（原则 2）；
- M11 完整检测分级接入后，归因事件驱动 §7.2 处置链；此前阶段处置输入 = 复检 verdict（degraded 持续超阈值 → 管理面人工触发处置）+ 用户上报滚动。

### 7.2 治理处置链（D6.4 终稿的流程化）

```text
输入：block_attributions(kind=third_party_block_defect, evidence_json)
      —— 录入口 = A8（Basic 管理面；M11 归因判定或 M12 仲裁结论为依据）
自动处置（单事务）：
  ① block_listings.status → delisted（delist_reason=归因 id）
  ② credit_events 落 credit_deduct + delist 两条
  ③ 引用应用失效标记：按 block_refs 反查引用应用，失效态可查
     （派生查询 block_refs × block_attributions，不新增 app_versions 列——
       不动 MS-2 已上线路径；M03 渲染消费端随阶段 C 接入）
  ④ 受影响买家赔付分录（pool_payout）落 market_ledger_entries（资金=保障金池）
  ⑤ 通知登记（notifications 机制随 M10/M12 排期，沙箱期以管理面板可见代替）
其他处置（非缺陷档）：治理违规 / 安全事件 → 同样走 delisted，但归因 kind 不同、
  无赔付分录；作者主动废弃 → deprecated（原则 5：提前 30 天通知）。
```

- 信用处置梯度（D6.2）：扣信用分（轻）→ 分成暂停（中，§5.2 L3 suspended）→ delisted 下架（重）；无保证金划转；资金追缴沙箱期无出口，统一结算域并入（MD-1）后按 M10 §3.6 顺序适用（「既是应用创作者又是积木作者」的跨域冲抵以并入时口径为准，登记于 docs/05 附录 A 决策新节）；
- 展示联动：delisted 积木从 market 目录消失；已购用户 entitlement 保留（可继续下载已购版本——"本地保留最后可用版本"承诺），但**不得新增引用**（registry 校验扩展同时要求目标块处于 listed 态）。

## 10. 阶段 A/B/C 拆分与出口度量

**接口先钉死原则**：A 交付的 §8 A1-A9 契约冻结；B 的投稿产物（block_version + verdict + listing）必须**无改动**进入 A 的上架链；C 只翻开关不改契约——三段可独立排期、独立验收。

| 阶段 | 内容 | 进入条件（gate） | 出口度量 |
|---|---|---|---|
| **A 平台侧市场基建** | 六张新表 + 状态机 + 自营 26 块 listing 挂接 + 买断记账沙箱（A3/A6）+ 权益 gated 分发（A5）+ 健康纳入（信任字段）+ 治理处置链（A8 + delisted 演练）+ A9 面板 | 无产品 gate（平台内部基建，阶段 4 启动即做；MD-1/MD-2 需先决） | ①自营块全部 listed 且 market 目录可读；②沙箱记账对账测试绿（分录代数和恒等 0、冲正链可追溯）；③一次完整 delisted 处置演练（含赔付分录 + 失效标记可查）；④A5 无权益 403 / 有权益 200+验签 |
| **B 创作者投稿面** | B1-B6 投稿→认证→上架向导 + registry 引用校验扩展 + 定价双轨 | **B-gate（显式挂 gate，非默认开放）**：①D-5' 达标（全部上架应用首跑 ≥80% 且 n≥5——现状未达：price_watch n=2）；②人工决策点确认 D-4 fail 登记"不进创作者开放投入"的约束不适用于积木作者投稿试点（或已被收窄场景集的覆盖证据解除）；③MD-1/MD-2/MD-3 已决 | 试点期内 ≥3 个第三方积木走完 投稿→认证→listed 全链（内测名单制，不公开注册）；向导页零人工辅助完成一次投稿 |
| **C 公开开放开关** | FORGE_MARKET_PUBLIC 翻转 + C1/C2 公开页 + M03 失效标记渲染消费 | **C-gate（显式挂 gate）**：①B 出口达成；②D-5' 数据在公开流量下保持达标；③后续覆盖故事成立——收窄场景集（A.9 R2 八场景）在第三方积木供给下的覆盖证据可呈报（补 D-4 fail 留下的覆盖缺口，人工判定）；④一次 delisted 治理处置在公开数据下演练 | **阶段 4 出口（PRD §15）**：积木作者供给 ≥ 平台自营 50%（第三方 listed 数 ≥13，自营 26 为分母；A9 面板实时可读） |

**背景约束（B/C 为什么必须挂 gate）**：D-4 复判终判 fail（2026-10-25 人工）已登记"不进创作者开放投入"；D-5' 试点首跑数据未到（hn_weekly 85.7% n=7 达标、price_watch n=2 不足）。顺序原则（PRD §15）：买家不买单，创作者生态不开放投入——A 阶段不面向创作者、不受此约束；B/C 投入前 gate 逐条人工判定并登记（docs/05 附录 A 惯例）。


## 11. 待决策清单汇总（项目决策登记惯例：问题/选项/推荐/回退链）

### MD-1 买断记账沙箱的形态与兑现路径

- **问题**：收款整体顺延（S-1、无支付通道）期间，付费买断如何运行、沙箱台账在收款接入时如何兑现；
- **选项**：a) 沙箱全双轨——付费买断照常下账（§5.2 分录真实记账），累计应结，收款接入后按台账一次性对账兑付；b) 沙箱期关闭付费轨，仅免费积木可上架（付费轨随收款一起开）；c) 平台线下人工结算（记账+转账）；
- **推荐**：a——分录只增不改保证可兑付，且能积累真实定价/转化数据为收款接入校准；b 牺牲双轨原则（D6.1）与数据积累；c 引入账外通道违反台账唯一性；
- **回退链**：a 的税务/法务风险人工判定不可接受 → 退 b（付费轨暂闭，代码按 price_mode 门控，开关复用 FORGE_MARKET_ENABLED 语义扩展）→ b 仍不可行才议 c。
- **状态：待决策（阶段 A 进入条件）**

### MD-2 受保护分发机制选型

- **问题**：D6.5 源码不可见的工程形态（§6 三选项 a/b/c）；
- **推荐**：阶段 A/B 用 c（明文 zip + license 校验清单 + 下载 gated + 签名溯源），收款接入时升级 a（加密包）；b 与离线承诺冲突，仅作最后手段；
- **回退链**：c 保护不足（出现实际泄露事件）→ a → b（须人工拍板豁离线）。
- **状态：待决策（阶段 A 进入条件）**

### MD-3 免费积木取用语义

- **问题**：D6.3"免费积木直接取用"是否落 0 元买断（order+entitlement+0 元分录）还是免登记直接引用；
- **选项**：a) 0 元买断——引用校验单判据（查 entitlement 一张表）、取用行为可审计、买断统计口径统一；b) 免登记直引——最简，但需另立引用审计表且市场转化数据缺失；
- **推荐**：a（"直接取用"语义不受损——0 元 purchase 即取用，一次请求完成）；
- **回退链**：评审认为 0 元分录污染台账 → b + 新增 usage_refs 引用审计表（引用校验改查 usage_refs）。
- **状态：待决策（阶段 A 进入条件）**

### MD-4 复合积木公开上架是否纳入首版

- **问题**：原则 2/PRD §3.3 将复合积木 public 上架列为阶段 4 能力，M14 首版是否同期收录（涉及权限并集重算、整体重发布链路、composite 分发形态）；
- **选项**：a) 首版仅原子积木（站点/通用），复合积木 public 再立卡；b) 复合积木 public 与原子积木同期；
- **推荐**：a——app-bound 机制已由 M10 §2.5 语义承载，public 化需要整体重发布 + 权限并集扩大重新授权的完整链路，首版范围爆炸风险高；listing_type 字段已预留（§4.2）；
- **回退链**：产品要求同期 → 复合积木 public 仅允许"平台代运营上架"（作者投递、平台打包签名发布），自动通道不开放。
- **状态：待决策（阶段 A 进入条件）**

### MD-5 信用处置体系的落表归属

- **问题**：credit_events（D6.2 信用分/分成暂停/下架流水）挂在 M14 域内自建，还是等待 M12 管理后台统一建设；
- **选项**：a) M14 域内落表（credit_events 六字段，处置链事务化）；b) 归 M12 统一账号信用域；
- **推荐**：a——D6.4 处置链要求归因→下架→扣分→赔付分录**单事务原子完成**，跨模块等待会拆散事务边界；M12 后续只读消费；
- **回退链**：M12 建设时判定需统一信用域 → M14 表迁并 M12（迁移卡，attribution_id 关联保留）。
- **状态：待决策（阶段 A 进入条件）**


## 12. TDD 验收锚点

1. **状态机全边**：draft→submitted→certifying→in_review→listed 与 rejected→submitted 重提、listed→delisted、listed→deprecated、delisted→relist 全部可走通；上架域不出现 `suspended` 命名；
2. **认证门槛**：verdict≠pass 的 run 不可挂入 listed（复用 registry 注册判据负例）；C0 积木提交 → 422；
3. **买断幂等**：重复 purchase 返回同一 order_no + entitlement_id 且 `X-Idempotent-Replay: true`；
4. **分发 gated**：无权益请求 A5 → 403；有权益 → 200 + `X-Forge-Digest` 验签通过 + 包内检索 `tests/golden/` 为空 + `META/license.json` 在场（MD-2 选 c 时）；
5. **台账守恒与不变量**：付费买断三段分录代数和=0；冲正组代数和=0 且与原分录组镜像（reverses_entry_id/attribution_id 齐全）；pool_payout 累计 ≤ pool_inject 累计；`amount_cents`/`entry_kind`/关联字段任何 UPDATE 被拒绝，`status` 仅允许受控流转目标值（非流转目标拒绝）——schema/服务层双重断言；
6. **处置链事务性**：录入 third_party_block_defect → delisted + credit_events×2 + 引用应用失效标记可查 + pool_payout 分录，五步同事务（中途注入异常回滚断言）；
7. **信用处置**：share_suspend 后在途 author_settleable 分录 status→suspended、新买断分录 L3 直接 suspended；share_resume 后原分录 status 流转回 available、新分录直接 available；作者结算摘要（A6）分桶正确；
8. **引用校验**：应用组合引用第三方积木无权益 → 422（文案含"先获取该积木"指引）；delisted 积木不得新增引用；权益存在且 listed → 通过；
9. **展示铁律**：market 目录/详情任何通过率必带 n；样本不足渲染"数据不足"；health 档 stale 渲染"待复检"；页脚声明一字不差；
10. **定价双轨**：free/priced 校验（priced>0、整数分）；涨价后既有 entitlement 的 amount_cents 快照不变；
11. **门控两态**：FORGE_MARKET_ENABLED 缺省 → A/B 段全部路由 404；开启后契约测试全绿；FORGE_MARKET_PUBLIC 翻转前后同一套测试通过（C3 契约零变更）；
12. **出口度量可算**：A9 面板供给比 = 第三方 listed ÷ 自营 26，构造数据可复算（阶段 4 出口判定数据源）。
