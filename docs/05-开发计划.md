# 05-开发计划（全程 AI 开发）v1.0

> **前提**：所有实现工作由 AI 编码 Agent 执行；人类负责**决策点、验收与方向纠偏**。本计划的目标是让 AI 开发像流水线一样可预测：每个任务原子化、验收命令前置、证据强制归档。
>
> **事实来源（只读锚）**：`docs/01-产品文档.md` v14.2、`docs/02-技术架构.md` v8.2、`docs/03-模块设计/`（M01-M16）。
>
> **日期**：2026-10-14


## 1. AI 开发纪律（总则，优先级最高）

| # | 规则 | 说明 |
|---|---|---|
| A1 | **锚文档只读** | docs/01/02/03 是唯一事实来源。实现中发现文档矛盾 → 停止任务 → 上报，**不得自行仲裁**；修正文档是独立任务卡 |
| A2 | **原子任务** | 每张任务卡 ≤1 个 AI 工作日当量；一次只做一张卡 |
| A3 | **验收命令前置** | 先写验收（测试/脚本/演示命令）再写实现；**完成声明必须附验收命令的实际输出**，无输出视为未完成 |
| A4 | **评审门** | 每张卡过 AI 评审员（code-review）；跨模块接口变更需"会签"——重新评审消费方模块文档章节并更新 |
| A5 | **禁止顺手改** | 跨文件重构、依赖升级、风格统一、超出任务卡边界的"改进"一律单独立卡 |
| A6 | **上下文预算** | 每张卡开始时重读锚文档相关章节（防长会话漂移）；接口以 §6 冻结清单为准，**冻结清单里没有的接口不得调用** |
| A7 | **测试真实性** | 验收命令由计划文档给出（§4 任务表），实现者不得修改验收命令本身；测试造假 = 任务失败 |
| A8 | **依赖白名单** | 技术栈锁定为 TDD §1.1；引入任何新依赖需独立决策卡 |

## 附录 A：决策记录（2026-10-14）

> 决策原则（产品负责人指示，2026-10-14）：D-1~D-5 按「开发最简、落地率最高、跑通优先」裁定；D-6 五项由产品负责人直接拍板。

### A.1 D-1 出网强制机制：v1 采用防火墙白名单/专用用户（原「降级二级」）

- **决定**：v1 落地机制 = Windows 防火墙出站白名单（默认阻断、仅放行 sidecar 进程）+ macOS PF 专用用户规则；自定义 WFP/PF 过滤器（原主路线）推迟到阶段 5 再评估；容器级（降级一级）不进入 v1。
- **理由**：Windows 防火墙底层即 WFP，属内核级强制，零驱动开发、全量机器可用；自定义过滤器只增加粒度，不改变「跑通」结论。
- **影响**：T1.01/02 由选型 Spike 转为机制验证；M05-a 工作量下调（原 No-Go 预估 +5~10 人日不再需要）；MS-1A 最大排期风险消除。
- **回退链**：验证点不成立 → 先补 WFP/PF 细化规则（仍不写驱动）→ 仍不行才评估容器级。

### A.2 D-2 轨迹格式 v1：采纳 M07 §4 现稿冻结

- **决定**：轨迹格式 v1 = M07 §4（数据模型）现稿，即日起冻结；会签改为「消费方一致性复核」——M02/M06/M08/M09 文档中轨迹相关章节与 M07 §4 无冲突即记通过；此后变更一律走 minor（触发四方适配评审）。
- **理由**：格式已完整定义，越早冻结越早解锁 T1.21 Recorder 与 T1.42 StructuredRunner；无实质分歧不必等会签仪式。
- **影响**：MS-1B 只剩复核动作；packages/proto 可立即按 M07 §4 开工。

### A.3 D-3 种子积木选站：原则定死，清单备案制

- **决定**：选站原则——法务安全度一票否决；仅标准/中变更站点；优先公开数据类、低反爬站点；登录类站点仅在平台自持测试账号时纳入。具体清单由 T1.60 按原则产出后写入本附录备案，**不设二次人工 gate**。
- **理由**：以原则约束替代逐站人工确认，消除 MS-1F 前的阻塞点；法务红线仍被原则覆盖。

### A.4 D-4 覆盖率实验：判定口径取简

- **决定**：需求样本取区间下限 **30 个**真实需求；单次整链运行产出正确结果即计「覆盖」；≥60%（18/30）→ 进阶段 2；不达标 → 收窄场景集重做种子库，不进创作者开放投入（维持 PRD §15 结论）。
- **理由**：口径前置写死后实验只剩执行；取下限样本量最省时。

### A.5 D-5 阶段 2 gate：口径维持原判

- **决定**：30 天退款率 <5% 且首跑成功率 ≥80%（标准/中变更站点桶），维持 PRD §15 口径不变，届时按实测数据判定，无预设降级。
- **理由**：两项阈值是买家信任底线，降阈值 = 透支平台信誉；维持口径不产生任何开发量。

### A.6 D-6 积木市场五项（产品负责人拍板）

| 子项 | 决定 |
|---|---|
| D6.1 定价 | 免费 / 作者定价（买断价）双轨；平台不设指导价 |
| D6.2 保证金 | 积木作者**不设保证金**；以信用处置（扣信用分 / 分成暂停 / 下架）替代；保障金池维持平台注资，买家赔付不变 |
| D6.3 分成 | **积木买断制**：应用创作者按定价一次性买断（免费积木直接取用）；买断收入按平台 30% / 积木作者 70%（复用应用侧框架）；购得后可在本人应用中引用，不按引用次数/时长/运行量持续计费 |
| D6.4 失效归因 | 新增「第三方积木作者缺陷」档：积木下架（delisted）+ 扣账号信用分；无保证金划转；受影响引用应用进失效态标记，买家赔付走平台保障金池 |
| D6.5 IP/源码 | 源码**不可见**：仅分发受保护形态 + 平台签名；反编译/转售/二次分发走创作者协议负面清单；license 单一默认条款不分级 |

- **理由**：买断制把结算压成「每笔买断一条分录」，消除按引用量持续结算的台账/对账复杂度；无保证金降低供给侧门槛；源码封闭保护积木商品性。
- **影响**：M14 §1 开放前提第 4 条（五项决策）已满足；M14 §2 原则 3 的按引用量分成口径废止。

### A.8 MS-1A 机制验证复核（D-1 追踪，2026-10-15）

> 数据源：`spikes/evidence/t1.01_report.md`（Windows 实测，四轮实机窗口 + 两轮诊断矩阵，全程快照自恢复）。

**Windows 四验证点（M05 §2.1）实测结论**：①子进程树继承阻断 ✅（子/孙两级即时 WSAEACCES，对照组策略前 connected）；②代理可达性 ✅（CONNECT 隧道采样 30/30，代理收到原始目标）；③绕过尝试被丢弃 ✅（raw socket/curl/备用网卡均阻断；「借用白名单镜像」按机制边界如实登记）；④附加延迟 p95 +7.09%（baidu，<10% ✅；hn.algolia 基线受跨境抖动污染为负值，登记不作依据）。

**L2 属性表（§2.3）**：白名单外阻断、镜像白名单两项实测成立；「组件出网唯一通道」「DNS 组件级阻断」实测**优于属性表预期**（默认出站 Block 连组件 UDP 53 一并阻断）。**判定：L2 保留属性全部成立，不触发 A.1 回退链。**

**部署前提（新增，M05-b 输入）**：Windows 上 WFP 对 **venv launcher 镜像**的程序放行规则不匹配（诊断实证）；sidecar 必须运行在**平台私有解释器安装**的镜像上（不与用户共享基础安装）——这是 D-1 路线在 Windows 的硬前提。阻断签名 = connect() 即时 WSAEACCES（非超时），`egress_denied` 归因与提示按此设计（M03/M05）。

**macOS 状态**：T1.02 规程（anchor 规则 + setup/teardown/verify 脚本）已交付、标注未实测；执行 blocked-on-hardware，**不阻塞组 B/C 开工**（里程碑图 MS-1B 不依赖 MS-1A 完成）。macOS 实测报告补入后，本节更新为双平台完整结论。

**工作量口径**：M05-Spike 估 3-5 人日（§11）——实际 Windows 半边约 1 个 AI 工作日当量（含诊断轮），估算维持不变偏保守；M05-a 不因本验证增加工作量，新增「平台私有解释器安装」打包项（估 +1-2 人日，归 M05-b sidecar 生命周期）。
