- Create: `spikes/run_t101_windows.py`

**Interfaces:**
- Consumes: T1.01-a `EgressProxy/proxy_worker/probe`、T1.01-b `firewall`。
- Produces: `python spikes/run_t101_windows.py`（venv 解释器）→ stdout 打印四验证点 JSON 判定；写 `spikes/evidence/t1.01_windows.log`（由 tee 承担）。退出码：0 通过 / 5 非管理员 / 6 目标全不可达 / 9 pythonw 缺失 / 7 机制验证点未成立 / 8 恢复失败（附手动恢复指引）。

常量钉死：

```python
TARGET_CANDIDATES = ("hn.algolia.com", "www.baidu.com", "example.com")   # 取前 2 个可达者
SAMPLES = 30
PYTHONW = Path(sys.executable).with_name("pythonw.exe")
```

执行序（`try/finally` 全程包裹防火墙变更；G12/G14）：

1. 预检：`is_admin`（false → 打印「需管理员：请以管理员身份运行一次本脚本，或启用系统 sudo 后重试」exit 5）；`PYTHONW` 存在（否则 exit 9）；G14 窗口告知打印。
2. 选目标：候选链逐个 `handshake_ttfb_ms` 直连探测（此时策略未变，兼作可达性预检），取前 2 个，全不可达 exit 6；解析并记录两目标的 IP（供无 DNS 的 raw 测试）。
3. 基线：每目标 `SAMPLES` 次 `handshake_ttfb_ms` 直连 → direct 样本；同时记录对照组：子进程 `python.exe -c tcp_attempt(ip)` → 期望 `connected`（留证据）。
4. 起 sidecar：`subprocess.Popen([PYTHONW, "spikes/egress_fw/proxy_worker.py", endpoint_file])`，轮询 endpoint 文件 ≤10s 且 TCP 可连通，否则归因 `proxy_not_listening` 失败（Review Focus 4）。
5. 防火墙变更：`snapshot_profiles` → `apply_outbound_block` → `add_sidecar_allow(PYTHONW 绝对路径)` → `policy` 现值断言已 Block（防规则未生效假阴性）。
6. 验证电池（组件进程角色 = venv `python.exe`）：
   - **VP1 子进程树继承阻断**：组件子进程 `python.exe -c tcp_attempt(ip,443)` → 期望 `timeout`（对照第 3 步 `connected`）；两目标各测一次。
   - **VP2 代理可达性**：驱动内 `handshake_ttfb_ms(host, proxy_endpoint=endpoint)` 成功（非 0 样本 ≥ 3 次试跑）且 `proxy_worker` 的 connect_log 出现 `host:443` 原始目标（connect_log 经 worker 落盘文件读取）。
   - **VP3 绕过尝试**：(a) 驱动进程（python.exe 角色）raw `tcp_attempt(ip)` → `timeout`；(b) `curl.exe`（无代理环境变量）直连目标域名 → 退出码非 0 且非 0 关联网络失败（对照：第 2 步前基线 curl exit 0）；(c) 「借用白名单程序」演示：`pythonw.exe -c tcp_attempt(ip)` → `connected`（证明白名单按程序路径生效；作为 **L2 属性缺口**如实登记——生产缓解 = sidecar 二进制签名 pin + 安装目录 ACL，写进报告）；(d) 本机多 IPv4 时逐 IP `bind`+connect 尝试，单网卡则登记 `single-nic N/A`。
   - **VP4 性能**：每目标 `SAMPLES` 次 `handshake_ttfb_ms(proxy_endpoint=...)` → proxy 样本；`delta_pct(direct_p95, proxy_p95)` 每目标 <10% 为过。
7. `finally`：`restore_profiles(snapshot)` → `delete_spike_rules` → `policy_matches(snapshot)` → 终止 worker、清理 endpoint 文件 → 打印 `"restored": true|false`；false → exit 8 并大字打印手动恢复指引（快照原文 + `Set-NetFirewallProfile` 命令）。
8. 汇总 JSON：`{"targets": [...], "vp1_block": bool, "vp2_proxy": bool, "proxy_saw_targets": bool, "vp3": {...逐项}, "vp4": {"per_target": {...}, "pass": bool}, "restored": bool, "window_seconds": int}`；exit 0 当且仅当 vp1∧vp2∧vp4∧restored（vp3 逐项如实呈现，(c) 为设计演示不算失败）。

- [ ] **Step 1: 实现驱动脚本**（按执行序；所有测量原语复用 T1.01-a，防火墙操作复用 T1.01-b；脚本内不写任何 netsh 文本）。
- [ ] **Step 2: 非提权干跑**。Run: `spikes/.venv/Scripts/python spikes/run_t101_windows.py`. Expected（当前 shell 未提权时）：exit 5 + 管理员指引文案（这本身就是预检路径的实测证据，归档）。若 shell 恰已提权 → 直接进入 Step 3。

  Expected: 退出码 0；JSON 中 `vp1_block=true`、`vp2_proxy=true`、`vp4.pass=true`、`restored=true`；日志含 G14 窗口告知与起止时间戳。

## 7. 风险与处置

| 风险 | 处置 |
|---|---|
| 当前 shell 非管理员且系统 sudo 未启用 | G13：预检 exit 5，打印精确指引（管理员终端运行一条命令），停卡上报；其余卡（a/b/d/T1.02）不受阻 |
