## 2. Review Focus（计划隐含、任务测试未覆盖的失败面；每行已挂归属测试）

1. **proto 超出冻结语义（发明字段/改名）**——逐字段对照 M07 §4 的评审由复核记录 + 终审承担；类型层面由「字段名集合 = 裁定字段名集合」的测试钉死。→ T1.20-b `test_frozen_field_names`。
2. **NDJSON 半行/尾随换行/空行解析**——解析器必须对空行容错、对残行报 FormatError 并带行号。→ T1.20-b `test_steps_ndjson_malformed_line`。
3. **主版本兼容判定**——`format_version` 形如 "1.0"/"2.0"/"1"：主段不同判不兼容，次段任意向后兼容；非法格式报错而非误判兼容。→ T1.20-b `test_major_version_gate`。
4. **快照与步骤的对应关系**——snapshots 文件集合必须与 steps.seq 一一对应（多/少/命名不符都报错，不静默）。→ T1.20-b `test_snapshots_one_to_one`。
5. **Python 校验器与 JSON Schema 漂移**——同一示例语料必须同时通过 Python 校验与 Schema 校验（自写对齐测试，不引 jsonschema 引擎）；负例语料双向拒绝。→ T1.20-b `test_schema_and_python_agree`。

## 3. 具体化裁定（proto v1 字段命名与表达细节；M07 §4 未钉死部分，变更走 minor）

| # | 事项 | 裁定 |
|---|---|---|
| C1 | `manifest.yaml` 字段 | `format_version: str`（"主.次"），`site: str`，`login_steps: [int]`（step seq），`time_sensitive_steps: [{seq: int, tolerance_ms: int\|null}]` |
| C2 | `steps.ndjson` 行字段 | `{seq, action, target_selector, dom_anchor, value, wait_condition, ts_offset}`——`value` 可缺省（M07 §4 `value?`）；`target_selector`/`dom_anchor`/`wait_condition` 允许 null 或缺省（wait/nav 步无目标选择器），非空时不得为空串（Schema minLength 1）；`action` 枚举 `click\|input\|scroll\|wait\|nav`（M07 §2/§3.3 与 M06 §3.2 同源）；`seq` 从 1 起**连续递增（+1）**——终审裁定收紧并登记（快照一一对应与 golden 逐步比对均依赖连续性；「重录该段」产物按重录后的连续序列重排）；`ts_offset` 毫秒、≥0 且非递减 |
| C3 | 快照命名 | `snapshots/{seq:06d}.html`，与 steps 一一对应 |
| C4 | `network.json` | `{"captured_at": ISO8601 str, "entries": [{url, method: str(大写), status: int, mime_type: str\|null, request_body: str\|null, response_body: str\|null}]}`；占位符格式 M09 细化，本层只保结构 |
| C5 | `golden/run_meta.json` | `{"environment_fingerprint": str, "captured_at": ISO8601 str, "source_cert_run_id": str\|null}` |
| C6 | golden 其余文件 | `expected_steps.ndjson` 与 steps 同 schema；`network_stubs.json` 与 network.json 同 schema |
| C7 | `trace_ref` | 类型 `str`、非空；具体分配规则归 M07 recordings，不在 proto 约束 |
| C8 | TS 聚合视图（终审登记） | `trace.d.ts` 的 `TraceDir`/`GoldenDir` 为 TS 侧整体视图类型（无独立序列化形态，Python/Schema 无对应物）——仅供消费方标注用 |
