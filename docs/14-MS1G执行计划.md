## 2. Review Focus（计划隐含、任务测试未覆盖的失败面；每行已挂归属测试）

1. **挑样**——看过帖子内容后把「能覆盖的」挑进样本，覆盖率虚高。→ T1.65c `test_sample_ids_subset_of_pool`（入样条目必须来自已存档池快照）+ `test_selection_is_mechanical`（同一池快照重跑选样结果逐字节一致：按帖子时间倒序取前 30，同刻按池序，无其他自由度）+ T1.65d `test_runner_rejects_sample_not_from_pool`。
2. **判定漂移**——正确性标准在看到运行结果后放宽。→ T1.65c 入样时每条预登记「预期产出形状」；T1.65d `test_run_record_carries_expected_shape_hash`（运行记录携带预登记形状的哈希，事后改样本文件与运行记录对不上即报错）。
3. **覆盖运行绕过产品路径**——用 spikes 脚本直跑凑结果。→ T1.65d `test_runner_requires_registered_blocks`（引用未注册块 → 拒绝运行，记 uncoverable，绝不落地产线脚本执行）。
4. **域内判定偷看答案**——把「可覆盖」当「域内」入样。→ 域判定产物（sample.domains）与覆盖判定产物（sample.attempt）分离落盘，且域判定先 commit（时间序可查）；T1.65c `test_domain_mapping_recorded_before_attempt`（同文件两阶段写入，第二阶段不得改第一阶段字段——测试钉住 attempt 写入时 domains 字段哈希不变）。

## 3. 具体化裁定（锚未钉死部分；变更走本计划修订登记）

| # | 事项 | 裁定 |
|---|---|---|
| C1 | 采样框 | **域内锚定**：池按 10 场景形状采集与入样（形状判定见 C8），域外需求不入分母、但池中域外条目的占比与分类作**旁证**记录在报告（需求分布证据）。理由：D-4 fail 路径是「收窄场景集重做种子库」，样本必须对场景域可判定才能指导收窄；PRD §14 的「种子用户访谈」在阶段 1 无种子用户，来源取「竞品社区需求区」单边 |
| C2 | 池规模与来源 | ≥60 候选（≥2× 样本量）、≥2 个社区来源；每条 `{id, source, community, url, title, excerpt, posted_at, fetched_at}`，URL 可溯源（C7） |
| C3 | 入样准则（预登记） | 帖子表达一个**具体的**自动化/数据需求，其形状落在 10 场景 ≥1 之内即入池；排除：明显违法/绕过反爬验证码/需原生 App 或桌面 GUI 自动化/纯咨询无具体需求（「有什么工具推荐吗」无目标数据）。排除决定记录理由 |
| C4 | 机械选样 | 池快照存档后，按 `posted_at` 倒序取前 30；同刻按池内顺序。规则零自由度，可由测试复算 |
| C5 | 覆盖运行路径 | forge_server 进程内经 Registry 查块 → Creator Center 干跑端点（或 chain 执行器）单次运行；执行器不 import 积木脚手架、不直调 main.run。需求恰好由 T1.64c 已发布应用满足时，可直接引用该应用执行（同为产品路径） |
| C6 | 覆盖判定 | **覆盖** = 存在已注册认证积木的参数化组合 ∧ 恰一次整链运行成功 ∧ 产出符合该样本预登记的预期产出形状。**未覆盖** = 无法组合（记录缺失能力/站点绑定原因，不运行）或运行失败或产出不符预期形状。站点绑定诚实判定：目标站点无对应积木即未覆盖 |
| C7 | 真实性 | 每条样本须可溯源：URL + 原文摘录（≥1 句需求原文）+ posted_at + fetched_at；无法溯源的内部设想不得入池。HN Algolia 条目以 API 返回为准（objectID 永久链接） |
| C8 | 域内操作化定义 | 10 场景形状清单（随规程备案 A.10）：s1 给定关键词在公开网络/搜索/API 检索并聚合；s2 读自己账号登录后的数据；s3 浏览目录/列表页抽取结构化条目；s4 从页面抽取文本/引文；s5 拉公开 JSON API；s6 仓库元数据查询；s7 监控高变更首页；s8 数据导出 excel/csv/markdown；s9 文本清洗/汇总/统计；s10 数值计算。一票定性：映射到 ≥1 场景即域内 |
| C9 | 单次运行语义 | 每条恰 1 次整链运行，不重试（瞬时网络故障同判未覆盖——这是阶段 2「首跑成功率 ≥80%」语义的前置演习）；运行时间窗与产物路径落判定记录 |
| C10 | 正确性判定人 | 预期产出形状由采集时登记（C3 工序），执行产出与形状的符合性判定由执行器做结构性校验（字段存在/类型/条数下限）+ 人工抽查复核标记（报告附复核列，D-4 呈报时人工可改判并留痕） |
| C11 | 时钟依赖 | T1.65e 前置 = MS-1F 收口（全库注册 + T1.64c 应用链验证完成）；预计 2026-10-18 时钟窗口后。a-d 卡无时钟依赖 |
| C12 | 报告出口 | `spikes/evidence/coverage/report.md`：分母/分子/覆盖率、未覆盖分类（按缺失能力：站点未覆盖/能力缺失/登录态/运行失败/形状不符）、域外旁证、判定记录索引；EVIDENCE.md 登记；**不写 docs/06 §4 结论行**——D-4 判定是人工决策点，报告只呈报数据 |
