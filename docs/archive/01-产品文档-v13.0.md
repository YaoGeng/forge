## 1. 产品定义

**对用户**：一个 AI 自动化工具商店。下载、安装、按引导授权，然后运行。工具能操作真实浏览器、处理本地文件、调用 AI 模型，完成过去需要人工重复执行的自动化任务。运行中有需要用户决策的地方（登录、勾选、确认），工具会暂停并提示。

**对创作者**：一个对话式开发工作台。说一句话 → Agent 自动探针目标站点 → 自动开发 + 自动测试 → 汇报结果 → 保存为工具模块。再做下一个模块，拖拽连线，点击执行测试 + 修复，发布。

**对平台**：通过 Marketplace 分发、Health System 保障、Automation Intelligence Layer 持续增强可靠性。

### 1.1 用户承诺

| 承诺 | 具体含义 |
|---|---|
| **装得上** | 下载 → 验签 → 自动装依赖 → Chromium 随包 |
| **跑得通** | 模型配置引导 + 凭证本机加密 + 运行时交互面板 |
| **持续跑得通** | Health 定时检测 + 健康评分 + 失效通知 + 自修复 |
| **坏了有兜底** | 失效可退款；创作者保证金约束维护 |

### 1.2 Marketplace 详情页信任字段

| 字段 | 说明 |
|---|---|
| 健康评分 + 最近检测时间 | 证明“现在还能跑” |
| 是否需要自配模型 Key | Token 完全自付，必须提前说 |
| 需要登录哪些站点 | 提前知情 |
| 运行时是否需要人工交互 | 如“运行中需要勾选商品” |
| 是否含强反爬站点 | 标注 best-effort |
| 支持系统 + 最低客户端版本 | 避免不兼容 |
| 失效退款政策 | 信任兜底 |

## 3. 核心对象模型

```
Capability（系统能力）
  ↓
Module（工具模块，创作者视角）= Component（自动化能力单元，系统视角）
  ↓
Workflow（模块连线形成的工作流）
  ↓
Application（自动化应用）
  ↓
Interaction（运行中的人机交互，横切所有层）
```

### 3.1 Capability

Runtime 提供的基础能力：Browser、File、Office、AI、Code、Data、API、Credential、Confirm、**Interact**、WASM、Docker。

### 3.2 Module / Component

**Module 是创作者视角，Component 是系统视角。**

结构：

```
Module / Component
├── Capability       # 声明所需系统能力（含 ai:<capability>, interact:<types>）
├── Interface        # 输入输出 Schema
├── Runtime Adapter  # Python / Node / Agent / WASM / Docker / API
├── Test             # 测试用例
├── Permission       # 权限声明
├── Interaction      # 交互声明（运行中需要哪些交互）
├── Probe Report     # 探针报告
└── AI Description   # 供 Creator Agent 理解的语义描述
```

### 3.3 Workflow

**模块拖拽连线形成的工作流。固定 DAG 骨架 + 节点内 Agent 智能。**

### 3.4 Application

最终交易单位。由 Workflow + 配置 + Schema + 信任字段 + 交互声明组成。

示例《小红书选品助手》：

```
关键词输入（启动表单）
  ↓
小红书笔记抓取模块
  ↓
笔记总结模块（Agent）
  ↓
【交互】勾选要上架的商品
  ↓
详情发布评论模块
  ↓
Excel 报告模块
```


## 4. Interaction Protocol（新增核心章节）

**平台核心能力之一。统一处理运行中的人机交互。**

### 4.1 设计原则

**所有运行中的“暂停 → 用户操作 → 恢复”都是同一件事。**

无论是登录、输入、勾选、确认、验证码、元素拾取、人工介入，本质上都是：

```
运行暂停 → waiting_user → 用户在交互面板操作 → resume → 继续运行
```

统一协议，统一 UI，统一恢复接口。

### 4.2 交互类型

| 类型 | 用途 | 示例 |
|---|---|---|
| `input` | 文本 / 数字 / 日期输入 | 请输入搜索主题、请输入选品规则 |
| `select` | 单选 / 多选 | 请选择分类、请选择时间段 |
| `confirm` | 确认 / 拒绝 | 确认提交评论？ |
| `login` | 站点登录 | 请登录小红书 |
| `captcha` | 验证码 | 遇到验证码，请手动完成 |
| `review` | 列表审查 / 勾选 | 请勾选要上架的商品 |
| `pick` | 元素拾取 | 请点击页面上的目标元素 |
| `takeover` | 人工介入 | Agent 卡住，请手动操作浏览器 |

### 4.3 交互规范

```json
{
  "type": "review",
  "title": "请勾选要上架的商品",
  "description": "从抓取的商品中选择要上架的",
  "items": [
    { "id": "p1", "title": "商品 A", "price": 99 },
    { "id": "p2", "title": "商品 B", "price": 199 }
  ],
  "actions": ["上架", "跳过"],
  "timeout_sec": 600
}
```

### 4.4 交互响应

```json
{
  "type": "review",
  "selected": ["p1"],
  "action": "上架",
  "confirmed": true
}
```

### 4.5 会话状态

`waiting_user` 状态携带 interaction id 与 spec。恢复路径：

```
用户操作 → POST /runs/{id}/resume {interaction_id, response}
  → 会话从 waiting_user → running
  → 组件收到响应继续执行
```

### 4.6 交互面板

运行中心有一个统一交互面板，根据 type 渲染不同控件：

| type | 控件 |
|---|---|
| `input` | 文本框 / 数字框 / 日期框（按 schema 渲染） |
| `select` | 下拉 / 单选 / 多选 |
| `confirm` | 是 / 否按钮 |
| `login` | 内嵌浏览器 + 完成按钮 |
| `captcha` | 内嵌浏览器 + 完成按钮 |
| `review` | 列表 + 勾选框 + 操作按钮 |
| `pick` | 内嵌浏览器 + 元素高亮 + 点击选择 |
| `takeover` | 内嵌浏览器 + 提示 + 完成按钮 |

### 4.7 预声明输入 vs 动态交互

| | 预声明输入 | 动态交互 |
|---|---|---|
| 来源 | `app.json#user_input_schema` | `runtime.interact.ask()` |
| 时机 | 启动前一次性收集 | 运行中暂停 |
| 示例 | 搜索主题、选品规则 | 登录、勾选、确认 |
| 实现 | 启动表单 | 交互面板 |

**UI 风格一致**，工程实现分开。

### 4.8 创作者调试与用户运行共用协议

- 创作者在 Creator Workspace 调试时，Agent 发起的交互显示在调试区；
- 用户在运行中心运行时，组件发起的交互显示在交互面板；
- **同一套协议，同一套控件**，宿主不同。


## 5. 基础模块：模型中心与凭证

**模型中心是所有用户的通用基础设施，不是买家专属。**

### 5.1 模型中心

**创作者和买家都是用户，都需要自己的 API Key。**

| 用户角色 | 用途 |
|---|---|
| 创作者 | 驱动 Automation Architect Agent、CodeAct 执行器、Agent 节点 |
| 买家 | 驱动应用运行时的 AI 调用 |

**支持三种接入方式**：

- 内置模型提供商：OpenAI、Claude、Gemini、DeepSeek、GLM、本地模型；
- 聚合平台：OpenRouter、词元世界等；
- 自定义提供商：兼容 OpenAI / Google API 格式。

**能力分级**：`fast` / `reasoning` / `vision`，由模型中心映射到具体模型。未配置的级别回退 `fast` 并向用户提示。

**Token 模式**：完全用户自付，平台不经手模型调用，不补贴、不代付、不抽成。

**首次使用引导**：任何 AI 相关操作（创作者开发、买家运行）首次触发时，如未配置模型，弹出引导：推荐模型 → 跳转申请页 → Key 自动验证 → 回到当前操作。

### 5.2 凭证管理

- 加密保存 API Key、Cookie、OAuth、Token：仅存储用户本机（DPAPI / Keychain / safeStorage）；
- 服务端不存储用户凭证；
- 应用无权直接读取；
- 用户可撤销授权。


## 6. Automation Intelligence Layer

### 6.1 Development Skill

| 规则 | 示例 |
|---|---|
| 禁止裸调用 | 禁止 `requests.get()`，必须用 `runtime.browser.open()` |
| 禁止裸库 | 禁止 `pip install openpyxl`，必须用 `runtime.excel.create()` |
| 必须生成测试 | test.yaml、sample_input.json、expected_output.json |
| 必须声明能力 | capability.json 声明所需能力 |
| 必须声明交互 | 涉及运行中交互的，必须声明 `interact:<types>` |
| 必须先探针 | 涉及新站点的模块，开发前必须自动执行探针 |

### 6.2 Runtime Skill

```python
runtime.browser.open(url)
runtime.file.read(path)
runtime.excel.write(path, data)
runtime.ai.chat(messages, capability="reasoning")
runtime.credential.request("1688_login")
runtime.api.request(url, credential=handle)
runtime.docker.run(image, command)
runtime.wasm.invoke(module, func, args)
runtime.probe.site(url)
runtime.interact.ask(spec)
```

### 6.3 Quality Skill

| 检查项 | 说明 |
|---|---|
| 测试生成 | 每个组件必须有测试用例 |
| 异常处理 | 必须有错误处理和重试 |
| 性能检查 | 关键路径必须有超时控制 |
| 权限检查 | 不能过度申请能力 |
| 交互检查 | 交互声明与实际调用一致 |
| 安全扫描 | 依赖 SCA、静态检查、提示注入防护 |

### 6.4 Marketplace Skill

| 能力 | 说明 |
|---|---|
| 填写描述 | 生成应用描述、功能列表 |
| 生成截图 | 自动生成应用截图 |
| 定价建议 | 根据复杂度和场景给出定价建议 |
| 版本说明 | 生成版本更新日志 |
| 信任字段填充 | 自动标注 Token 模式、登录站点、**人工交互**、强反爬 |

### 6.5 Data Flywheel

| 数据资产 | 来源 | 用途 |
|---|---|---|
| Selector 漂移库 | Health 检测 + 用户失败上报 | 记录 selector 漂移模式 |
| 修复手法库 | 创作者修复历史 + 平台自修复 | 记录有效修复手法 |
| 失败模式库 | Execution Monitor 全链路日志 | 记录高频失败模式 |
| 站点指纹库 | 探针 + Browser Runtime 被动采集 | DOM 特征、反爬策略、登录流程 |
| 用户修复确认数据 | 创作者确认/拒绝自修复结果 | 训练自修复 Agent |
| **交互模式库** | **Interaction Protocol 日志** | **记录常见交互类型与用户响应模式** |

### 6.6 Auto-Repair Layer

| 功能 | 说明 |
|---|---|
| Selector 自动修复 | 检测到 selector 失效后自动尝试修复 |
| 修复验证 | 沙箱中自动运行测试用例验证 |
| 创作者确认 | 修复成功后通知创作者确认 |
| 修复历史 | 存入数据飞轮 |

## 7. Browser/CDP Runtime

### 7.1 核心差异化

**打开浏览器 → 看到 DOM → 截图 → 分析 → 修改 → 重新执行。**

### 7.2 调试链路

```
Agent ⇅ MCP
BrowserAgentBridge
  ⇅
Browser-Use（stealth=True）
  ⇅
Patchright Chromium
  ⇅ CDP
```

### 7.3 探针（Probe）

```
识别目标站点
  ↓
启动 Browser/CDP Runtime
  ↓
访问目标页面
  ↓
采集：DOM / selector 候选 / 登录流程 / 反爬信号 / 网络请求
  ↓
生成探针报告
  ↓
写入站点指纹库
  ↓
作为开发计划的依据
```

### 7.4 反检测分层

L0 驱动替换 → L1 指纹一致性 → L2 行为模拟 → L3 代理 → L4 登录态 → L5 确定性脚本。

### 7.5 站点分级

| 等级 | 示例 | 执行策略 |
|---|---|---|
| low | HN、GitHub | Browser-Use Agent 主导 |
| mid | 知乎、微博 | Agent + 平台 stealth 脚本 |
| high | 小红书、1688 | 确定性脚本骨架 + Agent 补位 |
| extreme | Cloudflare 保护站点 | 本地 best-effort，含登录态需人工介入 |

> **合规边界**：平台不提供绕过验证码的能力。遇到验证码时通过 `runtime.interact.ask({type: "captcha"})` 通知用户手动处理。


## 8. Creator Center

**定位**：对话式开发工作台。说一句话产出模块，拖拽连线即应用。

### 8.1 创作者理想流程

```
1. 对话框输入需求
   “帮我写一个小红书首页根据主题抓取相关笔记内容并总结的功能”
                    ↓
2. Agent 自动探针
   识别站点 → 采集结构 → 判断分级 → 生成报告
   如遇登录 → runtime.interact.ask({type: "login"})
             创作者在调试浏览器登录 → 恢复
                    ↓
3. Agent 自动开发 + 自动测试
   生成代码 → lint → Runtime 测试 → 失败自动调试
   如需输入 → runtime.interact.ask({type: "input"})
             创作者输入 → 恢复
                    ↓
4. 汇报结果
   做了什么 / 测试结果 / 需要的权限 / 需要的交互 / 注意事项
                    ↓
5. 保存为我的工具模块
                    ↓
6. 再做下一个模块
   “帮我写一个总结我想要的笔记，并点击详情发布评论的功能”
   （重复 1-5）
                    ↓
7. 拖拽连线
   两个模块在画布上连线，形成工作流
                    ↓
8. 点击执行测试 + 修复
   全链路跑通 → 失败自动修复 → 汇报结果
   交互在此阶段也会触发 → 创作者在调试区响应
                    ↓
9. 发布
   配置定价 / 描述 → 提交审核 → 上架
```

│ 我的工具模块库（可拖拽到画布）                  │
├──────────────────────────────────────────────┤
│ 画布区（模块拖拽连线形成工作流）                │
├──────────────────────────────────────────────┤
│ 调试区（Browser/CDP 实时可见）                  │
│ ├── 交互面板（登录/输入/勾选/确认等）           │

### 8.3 对话式开发

**Agent 处理**：

1. **需求理解**：识别目标站点、功能类型、输入输出；
2. **探针**：自动采集目标站点；
3. **开发计划**：生成模块设计；
4. **代码生成**：生成组件代码；
5. **Lint**：静态检查；
6. **自动测试**：真实 Runtime 中运行；
7. **失败调试**：失败时进入调试循环；
8. **汇报**：输出结果报告。

**汇报格式**：

```
模块开发完成

功能：根据主题抓取小红书首页相关笔记并总结
输入：topic: string
输出：NoteList

探针结果：
- 站点分级：high（强反爬）
- 登录要求：需要登录
- 执行策略：确定性脚本骨架 + Agent 补位

测试结果：通过（3 条笔记抓取 + 总结）

需要的权限：
- domain: xiaohongshu.com
- credential: xhs_login
- ai: fast

需要的交互：
- login（首次运行需要用户登录小红书）
- input（运行中可能需要补充主题）

注意事项：
- 强反爬站点，成功率 best-effort

[保存为我的工具模块]  [查看代码]  [重新测试]
```

### 8.5 画布与连线

- 拖拽模块到画布；
- 连线形成工作流；
- 接口兼容性实时校验；
- 交互兼容性校验：上游输出是否满足下游交互需求。

### 8.6 执行测试 + 修复

```
全链路跑通测试
  ↓
节点逐个执行
  ↓
交互触发 → 调试区交互面板 → 创作者响应 → 恢复
  ↓
失败 → 自修复 Agent 尝试修复
  ↓
修复失败 → 通知创作者 → 人工介入
  ↓
全部通过 → 汇报结果
```

### 8.7 失败回退机制

| 组件类型 | 最大自动调试次数 |
|---|---|
| 纯计算 | 5 次 |
| 含 Browser 无登录 | 15 次 |
| 含 Browser 需登录 | 25 次 |
| 含 Agent | 10 次 |

**卡住判定**：连续 3 次失败原因相同。

**人工介入**：Agent 报告 → 手动浏览器介入（推荐）→ 手动改代码。

### 8.8 发布流程

```
执行测试 + 修复通过
  ↓
配置应用信息（名称、描述、截图、定价）
  ↓
填写 Marketplace 信任字段（含人工交互标注）
  ↓
提交审核 → 自动测试 → 人工审核 → 发布
```


## 9. Application Health System

### 9.1 功能

| 功能 | 说明 |
|---|---|
| 定时测试 | 默认 24h；强反爬 6h；成本超阈值自动降频 |
| 页面变化检测 | 监控 DOM 变化，预警 selector 失效 |
| 失败分析 | 规则分类 + LLM 归因 |
| 自动修复 | 自修复 Agent 自动尝试修复 selector 漂移 |
| 创作者修复 | 自修复失败时通知创作者 |
| 用户通知 | 失效通知、恢复通知 |
| 健康评分 | 检测通过率 + 用户运行成功率 + 修复响应时效 |

**登录态组件检测边界**：用户凭证仅存本机，平台沙箱不持有。分级检测：无登录组件全量检测；含登录态组件仅公开页探活；登录后流程依赖用户本地运行上报。

**含交互组件的检测边界**：含 `input` / `review` / `confirm` 等交互的组件，平台沙箱无法自动响应。检测策略：使用默认响应（若组件提供）或跳过该节点，标记为“部分检测”。

**健康评分说明**：详情页必须注明“健康评分覆盖公开页检测；含登录态与交互的流程依赖用户运行上报”。

## 15. 产品一句话总结

> **一个让用户买到能直接运行的 AI 自动化工具、让创作者用自然语言生产这些工具的平台。**
>
> **用户侧第一卖点**：买到就能直接运行。

> **Browser/CDP Runtime** 是“能操作真实软件”的底座。
> **Interaction Protocol** 是“人机协作”的底座。
> **Application Health System** 是“持续能跑”的保障。
> **Automation Intelligence Layer** 是长期护城河。
> **平台只自研规范、权限、凭证、签名、健康、交互、结算——这些才是壁垒。**
