## 3. 对象模型规范

### 3.1 Module / Component 目录结构

```text
module/
├── component.yaml
├── interface.json
├── adapter.yaml
├── interactions.yaml     # 交互声明
├── probe_report.json     # 探针报告
├── main.py / index.js / prompt.md / module.wasm / Dockerfile / openapi.json
├── requirements.txt
└── tests/
    ├── test.yaml
    ├── sample_input.json
    └── expected_output.json
```

`component.yaml`：

```yaml
schema_version: 1
kind: component
name: xhs_note_fetch
version: 1.0.0
title: 小红书笔记抓取
capabilities: [browser, ai_fast, interact_input, interact_login]
permissions:
  - { type: domain, value: "xiaohongshu.com", required: true }
  - { type: credential, value: "xhs_login", required: true }
  - { type: ai, value: "fast", required: true }
  - { type: interact, value: "input", required: true }
  - { type: interact, value: "login", required: true }
runtime:
  adapter: python
  entry: main.py
ai_description: 根据主题抓取小红书首页相关笔记内容
```

`interactions.yaml`：

```yaml
interactions:
  - id: topic
    type: input
    title: 请输入搜索主题
    schema: { type: string, minLength: 1 }
    optional: false
  - id: xhs_login
    type: login
    title: 请登录小红书
    site: xiaohongshu.com
    optional: false
```

## 4. Runtime 架构

### 4.1 进程模型

```text
Electron 客户端
  ├── Renderer
  ├── Main
  ├── Runtime Sidecar（本地）
  └── SQLite

服务端（Marketplace / Health / 结算）
  ├── API
  ├── Worker / Beat
  ├── PostgreSQL
  ├── Redis
  └── MinIO
```

### 4.2 执行会话状态机

```text
queued → running → succeeded
              │  → failed（retryable? 重试 : 终态）
              │  → waiting_user（携带 interaction）
              │       → running（resume）
              → cancelled
              → partial_succeeded
```

### 4.3 Capability API

| 外观 | 权限类型 |
|---|---|
| `runtime.browser` | `domain:<host>` |
| `runtime.file` | `fs:<scope>` |
| `runtime.excel` / `word` / `ppt` | `fs:<scope>` |
| `runtime.ai` | `ai:<capability>` |
| `runtime.code` | `code_exec` |
| `runtime.data` | `fs:<scope>` |
| `runtime.api` | `domain:<host>` |
| `runtime.credential` | `credential:<id>` |
| `runtime.confirm` | `action:<kind>` |
| `runtime.wasm` | `wasm_exec` |
| `runtime.docker` | `docker_exec` |
| `runtime.probe` | `probe` |
| `runtime.interact` | `interact:<type>` |

### 4.4 Interaction 子系统

```text
组件调用 runtime.interact.ask(spec)
  ↓
InteractionBroker 校验 interact:<type> 权限
  ↓
生成 interaction id → 写入 interactions 表
  ↓
ExecutionEngine 将会话转为 waiting_user，携带 interaction spec
  ↓
客户端交互面板渲染对应控件
  ↓
用户操作 → POST /runs/{id}/resume {interaction_id, response}
  ↓
InteractionBroker 校验响应 schema
  ↓
组件收到响应继续执行
```

### 4.5 沙箱

| 级别 | 机制 | 场景 |
|---|---|---|
| 进程级 | 子进程 + Job Object / setrlimit / sandbox-exec | 本地轻量组件 |
| 容器级 | Docker / containerd | 服务端 Health、不可信组件 |
| WASM 级 | wasmtime / wasmer | 高性能、强隔离、纯计算组件 |

**防御边界**：进程级沙箱防意外越权，不防蓄意攻击。主防线为依赖白名单 + lint + 审核 + PermissionBroker。

### 4.6 日志与脱敏

统一 JSONL；内置模式 + 明文集精确替换；上报前二次脱敏。**交互记录也走脱敏管道**。


## 5. Browser/CDP 调试链路、探针与反检测

### 5.1 调试链路

```text
Agent ⇅ MCP
BrowserAgentBridge
  ⇅
Browser-Use（stealth=True）
  ⇅
Patchright Chromium
  ⇅ CDP
```

### 5.2 MCP 工具

Browser-Use 工具 + 平台扩展：`dom_snapshot`、`network_logs`、`console_logs`、`selector_pick`、`session_takeover_*`、`deterministic_script_run`、`probe_site`。

### 5.3 探针实现

```text
probe_site(url)
  ↓
启动 Patchright Chromium
  ↓
访问目标页面
  ↓
采集：DOM / selector / 登录流程 / 反爬信号 / 网络请求
  ↓
生成 probe_report.json
  ↓
写入站点指纹库
```

### 5.4 反检测分层

L0 驱动替换 → L1 指纹一致性 → L2 行为模拟 → L3 代理 → L4 登录态 → L5 确定性脚本。

### 5.5 站点分级

low / mid / high 三级完整支持；extreme 本地 best-effort，含登录态需人工介入。

### 5.6 CAPTCHA 边界

不提供自动绕过。命中 → `runtime.interact.ask({type: "captcha"})` → 用户手动完成 → 继续。


## 6. Automation Intelligence Layer 实现

### 6.1 Skills

五套 Skill：Development / Runtime / Quality / Marketplace / Probe。

### 6.2 静态检查器

| 规则 | 实现 |
|---|---|
| 禁止裸调用 | AST 禁止 requests/urllib/httpx |
| 禁止裸库 | 禁止 import 运行时自用包 |
| 必须生成测试 | 缺测试文件即失败 |
| 必须声明能力 | 与实际 runtime 调用一致 |
| 必须声明交互 | 与实际 interact 调用一致 |
| 必须附探针报告 | 涉及新站点的模块 |
| 异常处理 | 必须抛 ComponentError |
| 超时控制 | adapter.yaml 必须有 timeout_sec |
| 安全 | 提示注入、依赖漏洞、越权调用 |

### 6.3 数据飞轮

六库全部启用：selector 漂移库、修复手法库、失败模式库、站点指纹库、用户修复确认数据、**交互模式库**。

### 6.4 自修复 Agent

触发 → 候选生成 → 沙箱回归 → 创作者确认 → patch 热更新。


## 7. Agent 编排架构

### 7.1 对话式开发状态机

```text
intake（理解需求）
  → probe（自动探针）
  → plan（生成模块设计）
  → codegen（生成代码）
  → lint（静态检查）
  → test（Runtime 真实测试）
      ├─ 交互触发 → waiting_user → 创作者响应 → 恢复
      ├─ 通过 → report → save
      └─ 失败 → debug_loop → 成功/卡住 → human_intervention
```

### 7.2 连线后测试状态机

```text
workflow_test（全链路跑通）
  → 节点逐个执行
      ├─ 交互触发 → waiting_user → 响应 → 恢复
      ├─ 通过 → 下一个节点
      └─ 失败 → auto_repair
                  ├─ 成功 → 沙箱验证 → 继续
                  └─ 失败 → human_intervention
  → 全部通过 → report → publish
```

### 7.3 失败回退

类型化循环上限 + 失败指纹卡住判定 + takeover。

### 7.4 Token 计量

ModelRouter 统一记录 provider/model/tokens/cost。Token 由用户直付模型商，平台只做本地计量展示。


## 8. Application Health System

调度：Celery Beat。

分级检测：

- 无登录无交互组件：沙箱全量；
- 含登录态组件：公开页探活；
- 含交互组件：使用默认响应或跳过，标记“部分检测”；
- 登录后流程：用户运行上报。

归因：规则 + LLM。

健康评分：检测通过率 + 用户运行成功率 + 修复响应时效。

自修复：触发 → 候选 → 沙箱 → 确认 → 发布。

通知：创作者 + 用户。

## 10. 权限、凭证与安全模型

### 10.1 权限全链路

组件声明 → 应用聚合 → 安装授权 → 本地 grants → 运行时 PermissionBroker。

权限类型：domain、fs、credential、ai、code_exec、action、wasm_exec、docker_exec、probe、**interact:<type>**。

### 10.2 凭证

仅存本机；服务端不存储；CredentialHandle 不透明。

### 10.3 威胁模型

| 威胁 | 缓解 |
|---|---|
| 恶意上架组件 | 权限声明 + lint + 自动测试 + 人工审核 + PermissionBroker + 域名白名单 |
| 供应链投毒 | 依赖白名单 + 锁定版本 + SCA 扫描 |
| 凭证泄露 | 本机加密 + broker 注入 + 日志双层脱敏 |
| 页面内容提示注入 | 页面内容标记为不可信数据；高风险动作必须用户确认 |
| 应用包篡改 | ed25519 验签 + HTTPS + 客户端内置公钥 |
| Sidecar 被本机其他进程调用 | loopback + 一次性 token |
| 进程沙箱残留风险 | 防意外不防蓄意；主防线为依赖白名单 + lint + 审核 + PermissionBroker |
| 高风险动作执行 | `action:<kind>` 权限 + `runtime.confirm` 强制用户确认 |
| **交互欺骗** | **交互响应必须过 schema 校验；交互记录写入审计日志** |
| 付费包无设备绑定 | 包可复制为已接受残余风险 |
