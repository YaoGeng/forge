# T1.01 Windows 出网白名单机制验证报告（MS-1A）

> 计划：`docs/08-MS1A执行计划.md`；锚：M05 §2.1/§2.3（D-1 路线：防火墙出站白名单）。
> 执行日期：2026-10-15；环境：Windows 11 build 26200 / Python 3.12.10 / 零新增依赖（stdlib + PowerShell 内置 cmdlet）。
> 验证对象：Windows Defender Firewall（mpssvc/BFE 正常，无第三方网络过滤产品，SecurityCenter2 仅 Windows Defender）。

## 1. 机制实施形态（实测可用的那一版）

各 profile 默认出站 **Block**（快照原值 NotConfigured，窗口内临时变更，结束精确还原）+
程序镜像放行规则（`New-NetFirewallRule -Direction Outbound -Action Allow -Program <镜像绝对路径>`）。
角色映射：sidecar = 基础安装 `pythonw.exe`（白名单内）；组件进程 = venv `python.exe` 及其全部子/孙进程（白名单外）。

## 2. 四验证点实测（M05 §2.1）

| # | 验证点 | 结果 | 实测数据（evidence/t1.01_windows.log，窗口 117s） |
|---|---|---|---|
| ① | 子进程树继承阻断 | **成立** | 组件子进程与孙进程直连两目标均即时拒绝（`error:PermissionError`=WSAEACCES）；对照（策略前）同路径 `connected` |
| ② | 代理可达性 | **成立** | 组件经 `127.0.0.1:<port>` CONNECT 隧道 TLS 采样 30/30 成功；代理 connect_log 收到原始目标 `host:443`（`proxy_saw_targets=true`） |
| ③ | 绕过尝试被丢弃 | **成立** | raw socket 直连 EACCES×2；curl 直连 rc 0→7；备用网卡源地址 bind 直连 EACCES；「借用白名单镜像」演示=connected（机制边界，见 §4-3） |

## 4. 发现（对 M05-a/M06 输入；按裁定号索引）

1. **R8——venv launcher 镜像的程序放行规则不匹配（关键）**：对 `.venv\Scripts\pythonw.exe` 的 Allow 规则（含程序+端口组合）不穿透默认出站 Block；同形态规则对基础安装解释器镜像、`curl.exe` 等常规镜像即时生效；端口-only 放行则放行一切镜像。WFP 应用 ID 对 venv launcher 镜像的匹配存在系统级异常（Get-Process 显示进程镜像确为 venv 路径，存储规则路径亦正确）。**部署结论：sidecar 必须运行在平台私有解释器安装的镜像上（不与用户共享基础安装），这是 D-1 路线在 Windows 上的硬前提**；组件侧 venv 数量不限（防火墙视角统一为组件镜像，全被阻断，正合白名单语义）。
2. **R7——阻断签名**：egress_denied 的错误归因与用户提示（M03/M05）按「即时 WSAEACCES」签名设计，勿按超时等待。
3. **白名单按镜像而非按进程树**：白名单镜像内的进程可放行出网（本验证以 sidecar 私有镜像收窄）；生产缓解=镜像仅平台私有安装 + 二进制签名 pin + 安装目录 ACL（M05 §2.3 补偿控制）。
4. **R6——PowerShell cmdlet 错误不置退出码**：一切管理面调用须前置 `$ErrorActionPreference='Stop'` 并做结果在场校验（规则创建失败曾静默吞掉）。
5. **R5——`NetSecurity.Action` 枚举 JSON 序列化为数字**（NotConfigured=0/Allow=2/Block=4）：读取面必须源头 `ToString()` 归一。
6. **G14 教训**：第 3 轮窗口曾失控 26 分钟（基线采样遭跨境网络劣化拖长）——已加 600s 硬预算看门狗 + 逐样本容错 + 连续 3 采样失败快速失败；本轮窗口 117s。

## 5. 回退判定（A.1）

L2 保留属性（白名单外阻断、镜像白名单、DNS 组件级阻断）全部实测成立，**不触发回退链**。macOS 半边（T1.02）规程就绪待硬件执行，不影响本判定；复核记录见 `docs/05-开发计划.md` 附录 A.8。

## 6. 性能口径备注

本轮为 spike 筛选口径（M05 §2.1 ④：握手+TTFB 附加 p95 <10%）；交付验收口径为 M05 §10.7 代理总附加 p95 <100ms（局域网目标，M05-a 承载）。跨境目标（hn.algolia）基线抖动大，附加率以同窗口同目标成对采样为准（本报告 baidu +7.09% 为有效样本；hn 负值系基线污染，登记不做依据）。
